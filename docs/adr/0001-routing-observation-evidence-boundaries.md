# 底层路由观测与证据边界

记录日期：2026-09-10。状态：既有讨论共识及案例 2 的首次建号、指定 UPDATE 关联规则已获用户确认；关联规则仍为文档级设计，未实现、未运行验证。此前样本只读核对仅验证所记载的原始字段和计数；本轮仅记录文档，未修改机器合同、测试或实现。

Domeye 的已有历史数据需要同时服务检测、统计、研究和只读查询。决定保留原始观察，按证据条件关联身份和重建状态，接受有限可用与未知；代价是部分身份暂不合并、部分历史无法连续解释，以避免误合并、伪撤回和无依据的状态继承污染上层结果。

范围限定为[五个领域对象](../../CONTEXT.md)及其证据边界，面向整个项目，不局限于 B/C。本轮不涉及持续采集、存储选型、接口建设、全量重建或部署。

对所有尚未验证的底层设计保持克制：设计被接受不等于事实得到证实、算法经过验证或功能已经可用。仅陈述证据覆盖的范围，明确保留假设、未知与未验证项，不把一个正例推广成全量准入能力。

## 已确认的决策

1. **有限证据可以准入。** 会话边界不完整不妨碍保留原始观察；记录可用范围及限制，分别判断观察事实、快照状态和连续重建是否有依据。缺失、未知和读取失败不能补成零或成功。
2. **原始身份与稳定身份分离。** 保存 MRT 实际提供的 Peer 属性及来源；关联得到的字段明确标为关联值。稳定 Peer Identity 限定在单个 Collector 内，跨 Collector 不自动合并；属性变化时保留历史，没有依据不自动延续或合并身份。证据不足时分别引用，不据此断言是不同物理设备。
3. **实际会话与观测覆盖分离。** 会话身份、起止和跨片段连续性可以未知；首末记录、数据缺口或相同端点不能单独确定会话边界。多个未知片段不能合成一个虚构的“未知 Session”。
4. **观察粒度与状态变化分离。** RouteEvent 按原始路由元素记录，保留原始消息关联、来源内顺序及路径和属性；同内容的不同原始观察不按内容去重，同一原始元素重复导入不重复计数。RIB 条目不作为新宣告；消息数、路由元素观察数和状态变化次数分别统计。
5. **状态保留观测对象边界。** 重建依赖基线、按序路由观察、会话事实和覆盖信息。会话可确定时，逻辑范围为 Collector／Peer Identity／Session，路由对象区分 AFI、SAFI、Prefix；ADD-PATH 另保留原始 Path Identifier。路径、Origin AS 和属性是状态值，不替代对象身份。会话未知时只保留证据支持的有限状态；跨邻居、会话和路径的归并属于上层口径。
6. **历史时间与处理时间分离。** 保留原始观测时间及精度、RIB 快照时间、条目 Originated Time、导入和解析时间，另绑定查询时点。重建依据原始观测时间与可确认的来源内顺序，不随导入或解析顺序改变；时间冲突或衔接不清时标明时序不确定，跨 Collector 不凭时间接近推断传播或因果。
7. **断开不伪造成撤回。** 会话断开独立记录，停止旧状态的无条件延续，保留最后已知证据和限制；不批量生成原始数据中没有的前缀 WITHDRAW。Graceful Restart 的保留、stale 和清除行为需要相应证据及明确规则，不能由断开单独推断 Collector 已清空全部路由。
8. **恢复只覆盖新证据的对象与时点。** 当前判断与最后已知证据分别表达。缺口后的完整宣告或明确撤回，在归属可靠时恢复对应路由对象的判断；范围完整、时间可对齐的可用 RIB 可重新建立其覆盖范围内的状态。之后的继承仍受后续证据约束；新记录不恢复整个旧表，也不倒填此前缺口。
9. **结果版本绑定重建依据。** 结果绑定原始数据范围与清单、解析版本、Peer／Session 关联规则版本和状态重建规则版本。处理批次与数据版本分开；同输入、同规则重跑应一致，输入或解释规则变化产生可区分的新版本，被正式引用的旧结果保持可追溯，不能静默改写。完整制品的留存与恢复方式未在此决定。

## Peer Identity 关联补充（已确认）

Peer BGP ID 不作为每条观察都必须具备的关联条件。观察缺少该字段时，允许在有证据支持的关联有效范围内，以同一 Collector、规范化后相同的 Peer IP 和 Peer AS，唯一匹配且没有已知身份冲突的既有 Peer Identity；保存匹配依据、证据来源、适用范围与关联规则版本。关联取得的 BGP ID 必须标为关联值，不能冒充该观察的原始字段。候选不唯一、已知冲突或有效范围无依据时，不按这一规则确认关联，仍保留原始观察及未确认原因。

这一选择允许不直接携带 BGP ID 的观察参与有界身份关联，代价是关联依赖可追溯的解释规则，不能将匹配结果视为物理设备身份的证明。身份关联成功不表示 Session 已确定，也不表示 RouteState 可以连续重建。

第一版关联对已有证据支持的具体观察生效，不默认将首末观察之间填成连续有效期。同一稳定 Peer Identity 可以被多次、不连续地引用；中间观察仍需各自适用的关联依据，连续关联区间另需证据。假设 00:00 与 00:10 的观察已分别关联到 Peer P，而中间存在证据缺口，这只确认两处关联，不确认中间所有 UPDATE 都属于 P，也不确认 Session 连续；该例是假设场景，不是新增样本审计结论。

案例 2 限定正例的首次建号与逐观察关联条件已在后文确认；其他观察的具体准入条件，以及确认连续关联区间所需的依据仍待确定。本次选取的十五分钟样本窗口不是已经证明的身份有效期，本补充不授权跨文件或跨缺口无条件延续身份。

“同记录时点＋唯一端点匹配足以准入”是用户接受的 Domeye 有界解释规则，不是从 MRT 直接读出的身份关系。秒精度时间相同不证明物理时刻相同，也不证明采集期间没有身份变化；接受该规则，就是接受这种有限、可追溯的推断风险，而非宣称风险消失。原始字段匹配的样本核对不等于对该身份推断正确性或通用性的验证。

### 预期结果与禁止推断

在上述输入和设定初始状态下，已接受规则的预期结果为：条目 5 建立（或按相同依据复用）`P` → 物理记录 0 依据明确绑定的 RIB、同记录时点与唯一端点匹配关联到 `P`。这补齐的是一个指定观察的文档级正例，不是完成或验证整个 Peer Identity 算法。

不得据此确认：其他 UPDATE 已全部关联、`P` 在两个时点之间连续有效、IPv4／IPv6 端点属于同一物理设备、实际 Session 已确定，或 RIB 与 UPDATE 的状态重建切点已经对齐。原始时间与字段不改写；后续证据或规则变化须形成可追溯的新解释版本，不静默改写被引用的结果。
