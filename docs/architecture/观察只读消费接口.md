# 观察只读消费接口

状态：Reader 已实现并经本任务隔离 PostgreSQL/DuckLake 人工链路验证；解码差异纯函数已实现，Feature 持久化尚在验证。不是全站或真实归档验收。

## 固定输入与流接口

`backend/data_pipeline/bgp/archive/message_reader.py` 的 `ObservationReader(dsn, run_id, expected_snapshot, ordered_source_ids, batch_rows=512, batch_bytes=4194304, guard=...)` 只消费已完成快照。调用者显式绑定单个 run、精确 snapshot 和有序来源清单；拒绝候选、失败、错版、重复/未声明来源及读取前登记漂移。消费前与每个 SourceEnd 前还复验所选来源仍 validated，消息/元素回执仍等于构造时绑定值；不以新回执重解释旧 Reader。不读取 latest，不解析 MRT，不使用 Replay，不写观察库。跨 run 预热尚未实现。

`stream()` 按声明顺序产生 `SourceStart → MessageBatch* → SourceEnd`。三类记录均携带 run_id、snapshot、source_id。开始记录另含内容 SHA、role 和预期消息/元素数；结束记录分别提供实际消息、元素、STATE、EOR、LOCAL 和质量记录数。只有消息数与元素数分别匹配源回执才发出 SourceEnd；调用者不得提前将源标为完成。

MessageBatch 包含 messages、elements、byte_count、source_quality。消息按物理 record 顺序只出现一次，元素按消息内 ordinal 排列；消息和其后续元素可跨批次，使用 message_id 关联。STATE/EOR、无元素消息、空来源、源级与消息级质量证据均保留。元素携带原 Peer、local 端点、方向、epoch/microsecond、MRT 类型/子类型、path_id、路径键及原始属性/路径字节。批次按行与估计载荷字节限制；不可拆分的一条消息/元素组合或大记录可单独超限，调用方 guard 用于资源保护，估计值不是 RSS 上限。

`reference_batches(source_sha256)` 读取相同快照的原始词法参考行，核验参考来源回执及实际行数；不决定 pandas 推断或业务参考解释。该 Arrow 接口按行分批，调用者还须为大参考行实施字节与 RSS 保护。

## 解码决定与适用边界

协调已批准：新计算使用 MRT 真实字段，AS_PATH 取路径属性，ADDPATH 的 path_id 单列；LOCAL_ADDPATH 的旧 VP 分组取原 Peer ASN；ET 保留秒与微秒并按真实时间处理。普通 LOCAL 保留旧 Feature/Detection 的计数和私有投影推进行为。兼容计算包含双向观察，不是规范接收 RouteState，也不能无说明推成实际可见性。解码版本、算法版本、投影版本和参考版本分别绑定输出。

ADDPATH 文本错位及 ET 旧转换异常须另存解码差异：原观察坐标/字段、固定复现器版本、旧固定字段推导值或错误、新值、reason、decoder_version。共享 `observations/decoding.py` 的 `decoding_difference(row)` 产生此记录，`decode_element(row)` 仅补版本/方向标签、不改变真实字段；不要求再跑一套错误文本业务状态，也不声称修正结果与旧错位/失败结果数值等价。原件不因旧工具缺陷被判坏；历史适用性及旧历史实际 bgpdump 版本均为 Unknown。

## 工具复现证据

使用 RIPE NCC 官方 [bgpdump v1.6.2](https://github.com/RIPE-NCC/bgpdump/releases/tag/v1.6.2)，源码提交 `63fe1c50c7d07bb4c57d4fcc690696adc9b3c306`；官方发布包 SHA256 `7c6dc32c367590a527752ca84c727ab4cbedc16a5abe5384dc523e563907abe0`。Apple clang 17.0.0 (clang-1700.0.13.3)，arm64-apple-darwin25.6.0，执行 `./configure`、`make`，本机构建二进制 SHA256 `e0dd7eeb9f7a16261e03d969774cec13e539fb4b5a01d72bca25ff3754bba3b6`。二进制和构建目录在任务临时目录，不是项目依赖或历史生产版本证明。

`backend/tests/observations/test_observation_direction.py` 固定完整真实 stdout，并用手工二进制输入重新执行 `bgpdump -m <fixture>`：子类型 4/7 的 VP 为 64497、路径为 `64497 64496`；9 的路径前多出 path_id 42；11 的工具文本 VP 为本地 12654 且同样多出 42；ET 文本时间为 `100.123456`。旧固定下标路径读取会把 42 当路径，旧整数时间转换会失败。测试同时核验新解析器原 Peer 64497、真实路径及 path_id。以上是固定工具的人工 stdout，不能称为旧历史原始 stdout。后续补充实测：AS2 子类型 1/6/8/10 与相应 AS4 文本字段一致；IPv4/IPv6 RIB 普通与 ADDPATH（2/4/8/10）、IPv6 MP UPDATE 普通/LOCAL/ADDPATH 均复现；STATE 输出状态行，EOR 无文本输出，新观察仍保留零元素消息。解码差异规则只覆盖已验证的字段错位；组播/generic RIB 文本及其他未测格式的旧工具解释仍为 Unknown。

## 已运行验证

显式绑定本任务临时 PG，公共 produce → DuckLake 固定快照 → Reader 的八项测试通过：混合多 NLRI/LOCAL/STATE/EOR/空源、精确身份拒绝、读取前漂移拒绝、消息计数篡改不发 SourceEnd，以及消费前/流中分别修改来源状态、消息数、元素数均拒绝 SourceEnd。官方二进制 19 项格式对照及 4 项差异字段/身份测试通过。测试只使用合成字节和独立新建数据库，不读取真实 D/MRT，不修改共享服务。
