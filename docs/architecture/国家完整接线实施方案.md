保存变化的 source_rank 来自生产器 `[baseline, *update_sources]`，须绑定这份确切有序清单；manifest中额外RIB快照不能插入编号或擅自重置状态。同序游标外键、消息与元素数量、路径和参考外键全部核验。现有 `store.scan(dsn,run_id,table,...)` 各次自行解析snapshot，且非changes表未保证顺序，不能直接拼出固定多表视图。国家 adapter 应通过同一明确 expected_snapshot 的读取绑定，所有查询带固定catalog/schema/run/snapshot；资格或引用变化即失败。

## 3. 事件身份与逐事件基线

输入先固定全部 country business revisions 的枚举范围和选择规则：每个incident在固定Detection结果中取目标修订（默认最高完整修订），保留被替代修订引用；新结果键为 `(component_key, incident_id, revision)`。incident_id包含run语境，不保证跨run同一事件。旧legacy_ref是来源别名，不重建旧ID作为新主键。

本方案只消费单个固定保存态链。多个分别初始化的Stage1 run不能拼成连续链；跨run的baseline_mappings、changes没有明确连续链合同和证据时，不重建连续性，受影响事件按missing_baseline保留，准入由固定profile判定。

每事件记录 country、onset及原精度、detected_at及原精度、end及原精度、onset_cursor及其证据、carry_in_state、source_episode_ref、legacy_ref。只有证据明确把某cursor绑定到onset，才使用该cursor；触发消息cursor不可冒充起始cursor。已知onset时选其严格之前的保存态；onset未知时才允许明确标记pre-detection。秒级onset要求状态严格早于整个该秒，不能靠同秒文件序猜“之前”。

每事件的 baseline_id 由输入绑定、边界规则及实际 predecessor cursor生成；保存 boundary_basis、boundary_time_precision、boundary_ref、predecessor_cursor、mapping_ref、state_rule_version、完整性和缺口。不同事件可以有不同baseline_id；同国不同事件仍各自冻结。D首个RIB只提供共享扫描起始种子，不充当所有事件基线。

已知onset早于可用保存态或没有可证明的前态时，保留事件行及 `unavailable/missing_baseline`、缺少范围和绑定，不输出假空cohort或零轨。不把已知onset改成detected_at以绕过缺失。carry-in只有明确证据才known；否则left_censored。country_v2 runtime/country_reduction来源可单独保留，缺episode_id或身份链接时为Unknown，不能按国家和时间合并为同一事件。旧country event_start缺attacked_as只是legacy质量，不能阻断有明确country subject的新事件；真正缺起点则按上述边界处理。

## 4. 一次保存态扫描与游标激活算法

拟增加国家私有的保存态 adapter 和多事件调度器；不扩建通用恢复框架。复用S1成员选择和S2归约规则，先维持06e单基线结果等价，再增加下述调度。现有S2直接接收不同基线仍会拒绝，不宣称已经支持。

1. 固定输入合同，建立事件激活队列、每事件采样队列和结束边界。小表批读；事件数也设上限。按source游标扫描并检查原时间单调；不按时间重排冲突证据。合法时间回退或秒精度不足保留原件及质量，不标parse_failed。C1输出原序/原精度与unsupported_order能力限制；C2另行复核受影响事件或采样边界的unknown/unavailable范围，不猜序。
2. 从保存baseline元素和映射初始化**一个当前保存态视图**，校验初始化完成后才允许激活。该视图只赋值已保存after和明确invalidations，是国家计算工作态，不成为新的权威Observation状态。以prefix、origin及完整对象键建立索引。原LOCAL事实另存引用，不进入此视图。
3. 每次消费增量前，先处理严格位于其之前或需读取该消息前态的激活/采样边界。激活时从当前国家origin索引找候选prefix，再按prefix取全部方向、MOAS及unknown关系，调用S1规则冻结成员及分母。只保存事件相关成员和引用，不复制全网状态；未纳入的unknown来源另有审计引用。需要前态但视图已有不可定序变化时拒绝，不倒放猜测。
4. 每条保存变化仅更新一次共享视图。通过 `prefix → 活跃cohort` 索引更新固定集合归约；新前缀通过明确country归属路由到相关活跃事件，冻结首次资格引用。不同事件独立new_seen，不扩大原固定分母。变化处理延续统一身份/路径校验，包括最后样本后的输入尾部。
5. 每个采样读取state(t-)。消息时间恰等于t时先采样再消费；原精度无法区分时按既有严格规则拒绝。逐事件输出矩阵和聚合，批次立即落盘；最后样本后仍消费声明输入右端之前的事实并校验，右端本身不纳入。事件结束时释放活跃成员/聚合，保留已输出引用。
6. 所有输入、外键及输出计数验证完成，且每事件有完成或明确不可用记录后，才封存模块结果。失败部分保持candidate，不能靠部分表存在申请发布。

同一游标的STATE失效与元素必须按保存生产规则组成一个有序处理单元；任何激活和采样不得插在没有定义的单元内部。无范围gap使后续完整总体持续Unknown，有范围失效只影响列明对象；新A只恢复该对象。A原时点事实与B采样计算独立，不能用A覆盖B缺口或把B零写为observed_zero。

### 资源与扫描复杂度

令N为保存变化/失效/事实行数，R为当前对象数，E为事件数，M为全部事件实际冻结成员数，Ma为同时活跃成员数，H为必要输出行数，F为相关变化向活跃cohort的实际分发次数。目标为一次全局保存变化扫描，时间约 `O(N log R + E log E + M + F + H)`；元数据、路径及参考各一次索引构建，不能声称全任务只读一张表一次。禁止E次全量历史扫描或E次MRT/Replay。E×成员/样本的实际输出成本不可消除。

C2候选采用任务私有SQLite临时工作库保存当前对象、关联与定位索引；这是本片实现选择，未新增依赖。后续C3拟用Parquet保存最终矩阵，PG保存模块登记和查询副本，均尚未实施。临时库不作为可恢复检查点；失败重新执行本模块。内存只保留有上限的批、活跃归约/成员缓存及路径样本，超限可按键查询工作库，禁止全表fetchall。磁盘量为 `O(R + M + H + 路径/参考索引)`；PG若复制全部矩阵需另计同量副本，发布回执报告实际字节。扫描需要的消息/元素关联在固定快照上批量索引连接，不为每事件重复关联。

批内不得跨激活/采样边界提前合并同对象变化。设置行数、字节、RSS、单行大小、临时/结果磁盘、活跃事件及路径关系保护；无数据处理总时限。路径原字典只保存一份，事件保留关系统计、最多三份确定排序样本及原引用；完整证据在共享来源。必须用人工放大数据验证扫描计数和峰值，未测前不推算真实D吞吐。

### 12.3 一次建索引，分页只读必要正文

拟采用一个封存的只读SQLite索引文件作为C4派生读模型，不建PG矩阵副本，也不重写第二份全部C3正文。索引包含：事件及小型overview摘要、成员/窗口/峰值定位、每查询行的typed排序键与`(table, source_sequence, row_hash, file_sha, row_group, row_offset)`、实际引用posting、有限过滤集合的total/digest；行数级索引是明确额外成本，不宣称常量存储。矩阵/事实/路径原正文仍只在C3 Parquet。Summary派生值及静态展示小表标明来源序号与计算/投影规则。

离线流程拟为：

1. 完整消费一次C3 `ComponentReader.stream()`，只有最后完整ReadReceipt才允许索引完成；以全局序号存键与摘要，外部排序建立B-tree和集合统计，保留重复原证据。C3内部全量校验/暂存/文件SHA成本一并计入，不称只读一遍字节。
2. 读取固定Parquet footer与`_sequence/_row_hash`两列一次，建立物理row-group定位并与上步逐行摘要/计数交叉核对；不是再扫全列或按事件重复扫描。没有定位证明不开放快查。当前21文件布局可覆盖，batch=1的多row-group也必须测量。
3. 用完整输入生成overview及每个有限集合total/digest，核15轨/矩阵笛卡尔覆盖、关联键、原修订最高选择和源引用，再封存索引manifest/文件；fsync与候选不可见纪律沿用已接受方案。索引失败不影响C3，不能在query时重建、修复或晋升。
4. 新连接只读校验索引结构、集合计数/摘要及全部locator，再按所有页回读与C3原流投影比对。关联/缺行错误拒绝，不拿第一页做验收或总体汇总。

在线CountryQuery会话拟复用一个只读索引连接、固定Parquet句柄与有大小上限的footer/row-group缓存。每页以B-tree定位，按涉及的row-group分组合并读取，只解码/核对命中行及row_hash；不调用C3.page重新构造21表验证，不执行C1.stream、Detection Reader或全湖SHA。这里需要一个**待实现的受控固定C3读取接缝**，不是当前C3 Reader已经提供缓存会话：open时校验固定snapshot→文件布局，返回前仍复核资格和文件实体戳；未经该接缝核验不得直接读裸Parquet。

每次query前后由统一资格接缝校验P/build/profile、C3登记、Obs/Detection/参考与生产回执当前资格，以及相关固定文件实体戳；按角色批量PG查询，不逐事件/逐行往返。不能仅用TTL缓存资格而漏掉撤销。完整schema/catalog核对在open或实体变化后集中执行；缓存只能复用同绑定、未变实体的结构信息，变化则拒绝并关闭，不换最新版本。源清单实体戳检查仍可随来源/文件数增长，不能声称O(1)。该批量资格接缝与Q2现有verify如何复用/拆分须owner认可，未经确认不承诺消除391条开销。

### 12.4 稳定分页、完整性与成本模型

cursor携带/校验Token三字段、component_key、result/read_model及manifest摘要、incident/revision/cohort、request类型/规范筛选/排序/定义摘要、最后完整排序键、已返回计数；所有查询条件由同一固定selection再验证，cursor不是授权凭据。数值字段按数值排序，不能沿用Q1 JSON文本数值排序；source_sequence作为最终平局键，重复原证据不得按内容去重。拒绝跨P/build/profile/result/revision/cohort、改过滤或排序的cursor；换head不改变旧Token。

每页total来自封存的**整个请求集合**，不是本页长度。只支持上述有限筛选组合，分类/AFI/ASN/关系组在索引中有完整计数；样本范围用有序索引计算确定范围，不扫正文。若临时筛选需要扫K个索引键，先检查显式索引预算，超限返回query_budget_exceeded，不能给估计总数冒充精确。page返回page_scope_verified；最后一页只表示到达集合尾部，不证明调用者读过前页。`iter_query`从首键按同一请求流式读取并累计count/digest，尾部才发QueryReadReceipt；早停无该回执。预构建全体验证与本次读取完整性分列，不借用C2Completion/C3ReadReceipt冒称读完业务全页。

令H为C3全行数、I为派生索引/posting行数、E为事件数、A为ASN成员数、F为相关源文件数、p为页大小、g为该页命中的row-group数。建模约为全C3验证成本 + `O(H log I + I)`索引/排序 + 一次两列定位扫描；临时/结果盘为C3原件外新增`O(I + 15E + A)`键/摘要/小汇总，不新增PG `O(H)`历史正文。峰值含C3原有暂存、构建SQLite、排序和缓存，继续行/编码字节/RSS/磁盘保护，无处理总时限。

页成本为资格/实体检查`O(F)` + B-tree定位/计数（通常`O(log I + p)`，动态范围最坏需K个索引键）+ g组解码字节；不是必然O(p)物理I/O。当前C3行组由编码批预算限制，实际Parquet未压缩字节另测；稀疏命中最坏g≈p、旧大footer及冷缓存会放大成本。设max_page_rows/max_page_bytes/max_row_groups/max_read_bytes及缓存上限，超限明确拒绝，不截断伪装完成。若该布局不能满足实测，返回REPAIR讨论离线排序重布局及额外存储成本，不默默复制全矩阵进PG。无高频性能GO或实测吞吐承诺。
