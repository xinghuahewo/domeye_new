## Standards P2：初始化与异常清理

原反例已在本任务运行代码上复现：启动真实C2生成器后传入已有root，`FileExistsError`返回时临时country-c2目录仍在。修复把Writer初始化纳入外围输入流清理范围；无论构造、消费、登记失败，均尝试关闭输入、恢复原external_guard、关闭Writer。Writer内部也分别尝试关闭lake、spool、PG，不因前一项关闭抛错而跳过后一项。

正常消费后先关闭输入再封存，输入close失败不产生complete。主失败继续原样抛出，额外清理失败保留在异常对象的`cleanup_errors`元组；没有主失败则抛首个清理失败，其余仍可检查。fail登记本身抛错也不覆盖主错误。清理只针对本调用已持有资源，不删除指定root或其他组件文件；构造前已存在root的哨兵原样保留。构造中途不能完成登记的目录保留candidate，不冒充成功或自动恢复。

反例和周边验证使用实际启动的typed与正式run_saved流、真实SQLite/PG/DuckLake句柄：已有root、输入close抛错、消费主错误、fail登记后抛错、Writer关闭抛错、lake/spool关闭均抛错。独立断言所有必要清理均被尝试、真实底层句柄被关闭、临时目录清理、原guard对象身份恢复，以及failed而非complete。故障注入是在关闭真实句柄后抛出异常，不用单个happy-close mock冒充资源回收证明。若底层系统自身拒绝关闭，代码保证继续其他清理并保留错误，不声称能强制关闭失败的外部资源。

## Spec P2：对象引用的所属关系

原“键存在即放行”反例先在本任务得到错误接受，修复后拒绝。临时SQLite增加稳定对象身份索引（object_id→prefix/endpoint/path_id）、cohort固定方向索引、首次资格索引和正式STATE目标索引。DirectionPoint的每个对象不仅存在，还须匹配该行prefix/endpoint；该方向必须属于该cohort。观察证据进一步核prefix/endpoint/cohort及DirectionPoint对象清单，拒绝拿另一前缀或另一Peer的既有对象/观察凑成合法引用。

附近规则按原计算语义区分：PrefixPoint与PathSample的固定前缀/方向证据，NewDirectionPoint的固定前缀之外新方向及首次观察，NewPrefixPoint/FirstQualifiedRef的动态首次资格、原观察位置、origin引用分别核对。PathSample保留原有path/peer/mapping核对，并核原时间。不能把新前缀强塞进固定分母，也不能要求历史路径观察等于采样时当前状态。

同对象跨时点的presence/origin/path变化不改其稳定键；同prefix/endpoint的不同AddPath对象可以共同属于一个方向，多Peer仍是不同方向。Unknown不补零。正式STATE引用使用原有一次C1扫描中SavedInvalidation的message→object目标，核其确实涉及对应前缀和方向；PathSample的state_refs可含该前缀其他固定Peer的状态证据，不误缩为唯一路径Peer。typed fixture没有保存原STATE目标，仍明确仅有typed输入边界，不能声称其外部STATE源已审计。完整Reader重建组件内部索引并核关系；正式源STATE目标审计由封存证据与固定资格承接，Reader不重复扫描C1。

反例覆盖既有不同prefix、endpoint、cohort、观察证据、路径prefix、新前缀首次引用和新方向观察错配，以及正式STATE错端点；正例保留多Peer/AddPath、同对象announce/withdraw/恢复、unknown、首次资格后origin变化、新前缀、历史路径和完整原证据。
