## 接口与实际存储

入口 `component.produce_component(c1, grid, dsn, root, c2_options=..., **limits)` 消费正式 C2 流；`persist_stream` 供同一流的保存接线及明确的 typed fixture 使用。返回不可变 `ComponentBinding`。无 latest、head、自动恢复或重试入口。`ComponentReader(dsn, binding, c1=...)` 只读；`page(table, incident_id=..., after_sequence=..., limit=...)` 返回有界单页，`stream()` 返回 `ReadBatch`，全流末尾才有独立 `ReadReceipt`。正式组件不能省略 C1 绑定，typed fixture 的 input_kind 保持显式。

PG 的 `country_components.catalog` 每库一行 catalog UUID；`components` 每组件一行 candidate/failed/complete 登记；`event_index` 每组件 E 个最高选中事件，只保留 incident/revision/country/state/cohort/sequence/行摘要。事件定位使用该主键，不复制矩阵、路径事实或事件证据 blob。索引写入按行数及编码字节分批；完整索引复核使用服务器游标，不把 E 行缓存在客户端。

每组件一个 `country_<UUID>` DuckLake schema、21 张固定湖表。每类型一个 Parquet 文件，即使批量为 1 也不按行或事件产生小文件；空表有可核对的空 Parquet，但不登记为湖数据文件。使用锁定 DuckLake 扩展的 `ducklake_add_data_files` 注册绝对路径，关闭数据内联。同库后续组件复用已有 catalog 数据根，各组件文件与快照独立。

## 资格与封存顺序

Binding 同时包含 PG system identifier、database OID、catalog UUID、component UUID、schema、snapshot、schema version、manifest SHA 和绝对结果根。上游绑定包含 Observation/Detection 实际数据库身份和固定 run/snapshot，生产 execution 回执 SHA、C1 identity（11 类参考和规则）、时区、Grid/C2 参数及本片代码/依赖锁文件摘要。不同数据库内恰有相同 snapshot 数字也拒绝。

Writer 完整消费唯一末尾 C2Completion，检查原输出数量、事件覆盖、最高修订与原修订引用、基线、对象/路径/观察证据及窗口关系。正式封存另做一次固定 C1 流的引用审计，确认原观察/路径/STATE 与参考定位存在、原事实字段一致，且 InputCompletion 未变；这是明确额外输入审计，不重新解码 MRT、运行 Detection 或重算 C2，也不随事件数重复扫描上游。

先完成 Parquet、固定湖 snapshot 和新连接逐列/逐行摘要回读，再复制并复核 E 索引，移除临时 SQLite；文件及目录 fsync 后生成文件 SHA/大小/mtime 清单，再写 manifest 和 ready 并 fsync，末端复核上游资格，最后 PG 从 candidate 登记 complete。文件系统与 PG **不是一个原子事务**。异常保留 candidate/failed 供人工识别；ready 存在也不能越过 PG complete。失败不提升、不自动恢复，不改旧组件登记或文件。

事件 availability 使用 available/partial/unavailable；完整空枚举为 known_empty。它与组件封存 complete 是不同事实；None、unknown、缺基线不补零。Reader 每次核对固定身份、登记、ready、清单、上游当前资格及文件身份；连接时检查实际 schema、表数量、固定快照文件链接。单页只验证本页正文与上述固定元数据，**不宣称重审全部正文**。全流额外复核全部行摘要、序号、数量、内部引用与文件 SHA，最后才发 ReadReceipt；早停关闭清理暂存，没有完整读取回执。全流也不重新扫描上游正文，承接已封存源审计并复核当前资格。

## 资源与成本口径

默认批量 256 行、编码批字节/单行各 4 MiB、组件 1,000 万行、每事件 100 万行、进程 RSS 2 GiB、临时/结果合计 8 GiB，无处理总时限。Parquet 编码批受实际字节限制；读取根据各表实际最大编码行宽收紧 Arrow 批行数，再逐行检查。SQLite 缓存 8 MiB、临时操作用磁盘。C2 临时目录置于组件根并收紧到组件 RSS/磁盘预算；C1 guard 联动计入其临时目录。

RSS 为进程 ru_maxrss 高水位，包含库运行内存，并非只数 Python 对象。合计磁盘包括本组件结果、C2 暂存和存活的 C1 暂存；全量 Reader 另计其 SQLite 暂存。已绑定输入制品、PostgreSQL 服务目录不在该客户端合计内。预算是循环/批边界检查，不声称操作系统级硬配额或每条数据库内部语句都受本进程 RSS 限额控制。

manifest 中 direct_pg_calls 仅是 writer 显式登记/索引 SQL 包装器的计数，捕获时尚未执行最后一条 complete UPDATE；不能称为全部 PG 往返。数据库身份检查、连接/事务及 DuckLake 内部目录 SQL 另有开销。固定 Reader 对 21 张表做文件链接、schema、count 元数据查询；没有逐行 PG 正文复制，也没有每页全正文 SHA 扫描。实测 PG 服务端 statement 数另从本任务日志按组件数据库分离统计，包含事务与 DuckLake 目录工作，不等同客户端 API 次数，也不包含另外两个上游库的 SQL。

### M3 公开来源落盘的累计计量

四类上游经 `M3Inputs.read` → `M3Source.capture` → `SourceStore` 读取时，已落盘原行的累计行数、逻辑编码字节只作计量，不作为正常总量或时长的停止条件。全量视图、原序号、typed 摘要、完整尾回执及锁/current 验证保持原合同；批行数和编码批字节仍在输出原行前检查。

`SourceStore` / `M3Source.capture` 可显式传 `max_disk_bytes`，按 SQLite 主文件实际大小与已分配页数的较大者，加同目录 journal 等文件占用执行磁盘保护，RSS 与单行限制保留。兼容旧调用时，省略 `max_disk_bytes` 会使用旧 `max_bytes` 作为**物理磁盘预算**；该值不再限制已处理逻辑字节总和。`M3Inputs.max_rows/max_bytes` 保留配置兼容及正整数校验，不再截断累计流。`M3Source` 无磁盘 store 的驻留副本仍在 deepcopy 前执行行数/字节工作集保护。

本调整仅覆盖公开原流接入已有磁盘源，不解除 Canonical 历史、D 结果链、C2 科学状态、资格生成或 C3/C4 的其他限制，也不表示全天处理已经可用。上游有效原制品无需因此重产；Country 代码规则变化须按既有规则正常取得新准入，只有原完整上游 AD/回执保持一致时才可复用其绑定的既有 C3/C4，不改签旧准入或旧清单。

### 查询物理资源采样补充（已实现，fixture 验证）

查询路径的目录占用与进程峰值 RSS 检查使用私有 50ms 采样间隔，避免每 1000 个 SQLite VM 步骤或每行重复遍历目录。外部 guard、取消与原有实体/资格检查不受该采样门控；查询开始、完成和 M3 Reader 关闭前强制采样，根目录或限额变化立即刷新。失败不缓存为成功，超限仍报 `resource_limit:C4_working_set`，关闭阶段失败不生成成功回执。离线构建与 inspect 保持原检查频率。

50ms 表示成功采样结束后允许复用结果的间隔，不是阻塞 I/O 的最长延迟，也不保证零超调；RSS 仍为进程峰值采样，不是操作系统硬配额。本补充仅使用临时 SQLite/mock fixture 验证，未执行 PostgreSQL、真实数据生产或集成验收。


### 计算变化引用去重外置（已实现，fixture 验证）

正式 C2/M3 的 EventDriver 为每次 compute 调用复用本次 SQLite Stage 的独立引用域，保存完整序列化引用，不截断或用 `str()` 拼接。相同引用可被不同活动计算分别消费，同一计算重复引用仍报“变化原始引用重复”。磁盘路径不再因 `max_changes` 输入总量停止；`changes_read` 递增和原游标、时间、来源、Collector 验证以及输出顺序、值、Completion 不变。内存兼容路径仍保留 set 及其 `max_changes` 工作集保护。

生成器完成、显式关闭或异常只删除自身引用域；整个 Stage 关闭释放本次临时库。单条引用仍受原 `max_row_bytes` 限制，写入前后沿用 Stage 的实际磁盘/RSS/取消 guard。单条写入和域清理期间不通过 SQLite progress 中断写语句，以免 SQLite 回滚共享事务影响其他活动域；检查点不能保证阻塞 I/O 的取消延迟上限。清理不吞掉原取消或资源异常。删除后的 SQLite 已分配页仍由原磁盘占用检查计入，可供本次 Stage 后续域复用。

本片仅移除变化引用全集的驻留需求，不外置事件、成员、当前状态或其他上述剩余控制材料，不代表 Country 已无规模边界或全天准入通过。验证为临时 Stage/compute 与 C2 typed fixture，未执行 PG、生产者、真实数据或集成发布；后续准入按正常规则处理。
