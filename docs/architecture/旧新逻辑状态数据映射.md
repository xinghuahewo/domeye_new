### M06 Detection：调度次序与错误不能变成成功

[逐项记录](阶段0A盘点/M06-BGPDetection.md)。`init_detection` 初始化 Outage、Hijack、SubHijack、Leak；每条有效 UPDATE 保存 old origins/VP paths → 更新 BGPRib → Hijack → SubHijack → Leak → Outage。每个文件末调用 `update_outage_event_table`。这只是该模块内部调用顺序，不是 Resource→Feature→Detection 的数据流。

解析时丢 STATE、默认路由、任何含 `{` 的 A；W 无 path。单行异常被日志记录后 continue，文件异常被吞掉。新 `observation_dispatch` 必须保留该元素及错误、模块处理状态和完整/部分窗口质量，异常不得借用旧“函数返回了”作为发布成功。RouteState 每条只推进一次，计算接收同一个带原事件引用的 before/after 与旧投影；模块不能再次修改共享规范路由。

### M08 Hijack 与 MOAS

[逐项记录](阶段0A盘点/M08-BGPHijack.md)。状态 `prefix_event[prefix]` 包括 `moas_eventid,hijack_eventid,last_moas_time,is_moas_now,original_as,pre_vp_paths`；`moas_event_dict[prefix][id]` 保存全部 orig/moas 成员、hijacked/hijacker 的 ASN/name/org/country/descr/admin、开始/结束/时长、end_as、真假与过滤原因、等级说明、三段路径、event_info 及源表引用。另保存两类 init_id。新去向 `moas_state`（PG）、`moas_observation` 和 `hijack_revision`（历史）；消费者是六类事件详情与原 MOAS 资料对照。

主流程只在 origin 数量变化时处理：1→2 尝试开始；>2跳过；多→多、等数量成员替换跳过；2→1 结束并保存 next paths/end_as；2→0 不结束。基线已 MOAS 只设 is_moas_now，不伪造 onset。原始 AS 起源与 pre path 仅在初始化/恢复中维护，不保证每次正常 A 都刷新。

过滤顺序要保留：大于2、无效 ASN、AS_SET、私用 → 个人/未知组织 → prefix_info.route 扩展候选 → 双向 import/export → provider/customer → peers → sibling/同英文组织 → 两 ASN 历史 pfx2as 同前缀 → AntiDDoS → v4Peer/v6Peer/sibling_as。每个 reject 分支、原因及使用的参考快照应写 `rule_decision`；批准后规则冲突修正产生新 rule_version。返回“possible hijack”只是启发式候选，保留旧角色字段，不改成攻击事实。

等级按前缀域名、权威域名、重要域名及重要 ASN；阈值同 M07 的前缀级，重要 ASN 直接升 high。MOAS 开始/结束写库调用均被注释，但内存状态仍产生，DB 模块和字段仍保留；`moas` DDL 的 `eve_vp_pahts` 拼写与使用字段不一致（D10）。Hijack 真候选写详情和事件总表，结束更新开始时表。以完整 lifecycle/规则原因/路径集合对照，不能用“两边事件计数相等”验收。

### M09 SubHijack

[逐项记录](阶段0A盘点/M09-BGPSubHijack.md)。`prefix_event` 的 is_sub_hijack/id/last_time 与 `sub_hijack_dict` 的父前缀、父/子 ASN 集合字符串及各自静态属性、s/e/duration、真假/原因、等级说明、event_info、源表引用全部保存；空 `moas_init_id` 作为历史未使用属性登记，不启用。新去向 `subhijack_state/subhijack_revision`，阶段 2，消费者为事件详情。

`get_state` 对 IPv4/6 找最近父前缀，子/父必须在树，默认路由父跳过；IPv4 长度差>8拒绝，IPv6>3拒绝。注释“<=3”不代表 IPv4 规则。对不在父 origin 集合的子 origin 过滤：父 origin 原始数量必须1；个人/未知组织；prefix/parent 的 route 参考扩充；AS_SET/下划线/64511—65535或超上界；双向 import/export、provider/customer、peer、sibling、同组织、AntiDDoS、外部 peer/sibling。所有过滤原因与原集合保留，不把字符串化列表拆成一个可信单 ASN。

False→True 开始，True→False 结束；初始化已异常只记状态，不合成过去事件。Detection 仅给“本条变化的 prefix”调用，父路由变化不会主动遍历子孙重判；持续 True 期间父/攻击者集合变更也不产生新事件修订。详情把集合第一个成员拿来填描述，受 set 顺序影响，集合本体与描述必须分别保存。其等级评价输入是父前缀和父起源集合。新规范判断父变更重评属于 D12，不暗改旧结果。

### M10 Leak 与泄漏现象

[逐项记录](阶段0A盘点/M10-BGPLeak.md)。输入只 A，W 不处理；AS_SET 跳过，相邻重复 ASN 压缩后长度必须>3（恰3不判），逆向找 provider→customer←provider 谷形关系；`get_as_rel` 先 peer=0、customer→provider=1、provider→customer=-1、未知=-2；只有两侧都 -1 且 triplet stability<0.2 才生成现象。

状态 `prefix_event[prefix]={last_leak_time,phenomenon_id,event_id}`，两套 init_id；`prefix_path_dict[prefix]=True` 是运行以来前缀去重门禁，名字虽称 path dict，实际没有按 path 键；W 不清除。现象 `phenomenon_dict[prefix][id]` 包含 `s_time,leak_by,leak_to,leak_vp,as_path,prefix_ori_as`、三方 name/org/country/descr/admin、level/level_info/event_info；输出后删除现象，但 seen 门禁保留。新 `leak_seen_state` PG 与历史 `leak_phenomenon/leak_revision` 保存这些数据，后续按相同规则补算不能丢掉门禁历史。

先评等级（同域名/重要 ASN）；middle/high 才分配事件编号并做 `is_leak_event`：同ASN、个人/未知/同组织、AS_SET、64511—65535或超上界、双向 import/export 排除。不通过过滤仍已设前缀 seen，可压掉后续真实候选。现象写库调用被注释，合格事件写 leak_event 和 event；没有 end/duration/恢复判断。迁移必须将生命周期标为“结束信息未记录”，不能把空结束当 ongoing。循环未在首个 triplet 后 break，一条路径可产生多现象，后续报文才被 seen 跳过。基线 RIB 不调用逐路径 leak 检测，不能把全部 RIB 路径当首日 A。

本阶段未访问真实制品或库，实际输入文件清单、SHA256、资料版本和旧状态均 **Unknown，须阶段 0B/协调任务另行绑定**。这里只冻结依赖与判定方法，不把已有试点目录/状态当本次运行初态，不接管停止的 02-27—03-10 试点。

| 模块 | 必需基线/预热 | D一天自身不足处 | 缺失时可做/不可做 |

| 输入/规范状态 | D开始前或切点可对齐的RIB、至D开始的全部UPDATE、原Peer表/会话或缺口证据、参考版本 | 切点、同秒次序、来源覆盖与Session不由文件名证明 | 可保留raw及单RIB有限快照；不得称连续RouteState全准入 |

对照方式：先判断输入/参考/算法/初态是否匹配，再比较中间集合、逐窗字段和事件修订。匹配旧结果不可取得时，在新项目内建立可审阅、显式隔离的旧规则兼容实现，fixture和原始格式独立核验共同对照；绝不运行旧入口/环境。正常处理不设总时长上限，工具/监控等待超时不终止、不重启正常进程；保持磁盘/内存保护。本阶段没有启动这些动作。
