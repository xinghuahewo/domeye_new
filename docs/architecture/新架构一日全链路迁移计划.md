## 一、保留与统一的范围

“保留所有逻辑及数据信息”包括：计算公式与判断分支、阈值和外部资料、输入过滤、业务状态的建立与更新、数据库和文件输出、事件详情与证据，以及现有页面实际依赖的查询语义。旧恢复文件中的业务状态也应纳入映射，即使首轮不实现其自动恢复。

## 五、首轮发布方式与明确后置的工作

首轮使用独立运行身份、候选数据集和状态空间。**解析／观察入库必须先具备完整输入文件级 checkpoint**；算法所需的状态、窗口及活动事件照常计算并保存，其复杂业务状态跨阶段恢复仍后置。文件级恢复不表示任意业务阶段均可断点续跑。

每个 checkpoint 绑定有序输入及文件 SHA、解析版本与 schema 版本、完整提交制品及记录范围、解析覆盖和完成资格。只有完整提交并核验合格的文件才可作为恢复点；成功文件不重放，失败的当前文件以新尝试重做，不能混入未完成输出或产生重复。版本变化必须重新判断可复用资格，不能只凭文件名或已读进度跳过。checkpoint 仅证明相应文件的解析／观察入库完成，**不等于整批业务发布**。

原 726 失败已确认由一条内部 BGP 属性越界触发，不是运行时长或 OOM；已有 277 条 source receipts 不能称为恢复点。保留原失败批次证据，由 903b 判断修复对此前结果的影响，逐文件给出可保留／需重算清单及依据；不能直接接续原失败批或默认此前输出均可保留。

完成全部必要输出与质量核对后，再登记这次运行的业务发布。查询只读取明确的已完成发布，不扫描候选目录或读表的任意最新值。流程失败则保留失败信息和旧发布；解析／观察入库按合格的文件级 checkpoint 恢复，失败当前文件使用新尝试。后续业务阶段尚无合格恢复能力时，仍从其明确的输入边界重新执行，不把文件级完成资格扩展为业务状态恢复资格；跨库交付回执补偿等能力继续后置。

源文件保护、来源版本、准确报错、候选与发布分离、资源上限和 Web 只读消费在首轮保留，因为它们是数据对账与正确发布的必要条件。基础文件级 checkpoint、强制进程中断恢复验收和逐阶段性能记录提前到全天验证之前；复杂业务状态与活动事件跨阶段恢复、事务发件箱、备份演练、自动清理和持续调度留到阶段 6。本次已同步[存储 ADR](../adr/0002-layered-data-storage.md)的实施顺序说明，存储选择与后续目标协议保持不变。

**2026-09-13 运行时长补充（已确定）：** 数据处理不设置最大运行时长，正常运行就持续至完成。耗时估计与测量只用于观测，不能作为终止条件；处理命令、外层任务包装及监控程序均不得用总时长上限停止正常处理。单次工具等待结束或监控查询超时不等同于处理失败，不据此终止或重复启动处理进程。保留磁盘、内存等资源保护，实际处理错误、校验失败或资源保护触发时明确报告；本条不启动或恢复既有试点。

## 六、一日对账与验收方式

### 对照依据

优先使用输入、参考资料、规则及初态能够匹配的旧结果；必要时在新项目内运行固定旧规则的兼容实现，生成独立对照输出。再用原始格式 fixture 和独立集合／计数核验检查双方可能共有的错误，避免两套实现相同就被当作正确性证明。

历史结果缺少匹配的输入版本、阈值、初态或会话依据时，不承诺精确重现旧事件。明确哪些项可以比较、哪些只能验证字段保存或新规则预期；不能通过忽略差异或将缺项填零宣称无损迁移。

| 层次 | 核对内容 |
| --- | --- |
| 原始与观察 | 文件和条目数量、来源位置、消息关联、重复导入与不同原始观察的区别、原始路径及属性、Peer、时间、明确拒绝和缺口 |
| 路由与业务状态 | 前缀、Peer 路径、起源、ASN 前缀集合及索引一致性；窗口、正常范围、候选与活动事件等旧状态的保存位置和演化 |
| Resource／Feature | 单位、统计粒度、累计与清零、过滤、稀疏写入、窗口边界、前窗比较和正常范围；数字对照须绑定相同口径 |
| 六类异常及详情 | 判定分支、开始／变化／结束、等级、对象与关系、前后路径、MOAS／泄漏现象、原始依据；ID 如有变化保留确定映射，不能只比较事件数量 |
| 国家增强 | 固定分母与对象集合、ASN／Prefix 时点序列、路径明细、审计、趋势与跨页引用；未知不变零，窗口峰值不变时点事实 |
| 发布与查询 | 来源与计算版本、各结果覆盖范围、引用可解析、集合与摘要一致、分页稳定；失败运行不可被默认选中 |

全天调度前，先用人工多文件输入在文件处理和提交边界强制中断真实处理进程，再恢复并与同输入、同版本的连续运行对照。核对完整 typed 内容、来源顺序、全表计数与摘要，证明成功文件未重放、失败当前文件重做后无遗漏和重复；仅模拟异常、检查 receipt 数量或比较总行数不能替代此验收。903b 负责具体实现和 checkpoint 设计，0B 独立复核；本计划规定门槛，不重复模块技术设计。

逐阶段记录墙钟耗时（wall time）、处理量及其单位、输入／输出体积、主要查询耗时、重复扫描点，以及峰值内存的测量方法与作用域。注明覆盖哪个进程或进程组、哪段采样区间，区分进程累计峰值与阶段测量值；阶段总 RSS 以及 PostgreSQL／DuckDB 内存无法分离测量时明确写 Unknown，不能冒称独立阶段峰值。性能优化围绕实际瓶颈进行，不以关闭校验、丢弃观察或减少业务分支换取首日通过。

六类算法的迁入与 fixture 分支验收、D 当天实际出现的事件类型、历史事件的可比较程度分别报告。所有必需计算完成才称为一天全链路跑通；若部分输出受真实证据不足限制，则声明相应范围和状态，不能称该能力已完整覆盖。

## 七、前端底座替换与历史数据保留
