## 1. 原始事实接口

`read_source(source)` 顺序输出消息及其零个或多个元素。来源绑定压缩 SHA256；消息键绑定来源与零基物理记录，元素键另加序号。消息保存解压偏移、完整长度、原 MRT 类型/子类型、秒与扩展微秒、原字节摘要；所有属性通过原件定位与属性偏移/长度/digest追溯，路径字典保存原字节及有序段。字段不支持时保存消息引用和拒绝原因，整体质量不冒充完全支持。损坏、gzip EOF失败保留失败运行，不发布。

同元素重复输入幂等；同内容不同坐标保留两个观察。RIB元素动作恒为 rib_snapshot。Peer表位置不是稳定身份；UPDATE缺BGP ID时保持原presence=false。OPEN、STATE、EOR、未知消息没有路由元素也保留消息。

| --- | --- | --- | --- |

| P2 有界关联 | 明确绑定RIB身份参考，具体UPDATE与RIB记录时点精度相同，collector/IP/ASN唯一且无已知冲突；保存证据 | 同秒同IP/AS且唯一，原BGPID仍缺失 | 不同秒、两个候选或BGPID冲突均不关联；不推广为区间 |

有限事件态的 before 可引用上次已知证据，但必须分开 `before_presence=unknown` 与 `last_known_presence=present`。只有 S2 有据连续范围内，before 才是有效前态。A替换时规范起源索引删除旧值；W只影响精确AFI/SAFI/prefix/path-id对象。ADD-PATH缺失与值0不同。相同原元素不再推进状态。

原事件时刻的判断不证明实际网络状态；对于秒精度同秒多元素，查询必须允许游标定位，不能假装有未记录的微秒时间。未处理对象和范围外查询返回unknown。

## 3. 存储与发布接口

`produce(manifest, storage, rules, limits)` 从固定输入一次运行。历史消息、元素、Peer、路径字典、关联、片段、状态变化写入DuckLake管理的Parquet；DuckDB负责批量写入及读取。PostgreSQL保存输入登记、运行状态、批次游标、规范当前态及业务发布；DuckLake自己的catalog独占文件/表/快照权威。Domeye仅引用其快照与表，不复制文件目录。

候选运行输出全部表、完整质量与引用计数之后，才允许登记阶段1模块发布；此发布不表示阶段2业务或Web已可用。异常保留candidate/failed，公开读取入口只接受完成发布，且绑定DuckLake快照。独立运行不重用失败状态，不实现checkpoint、重试或outbox。路径字典复用值，消息与元素不丢；按有界批次写入，不逐UPDATE往返PG，不把全状态存成大JSON。

## 7. 独立复核修正与二阶段回放（阶段 1 历史实现）

独立复核对8efd990提出三类P1；本节修订早期实现描述，后续以本节和实际新冻结代码为准。

1. **内容身份与来源身份分离。** `sha256`只标原件压缩字节；`origin_uri`显式标识原始采集来源位置；`source_id=SHA256(collector、origin_uri、内容SHA)`标观察来源版本。本地`path`仅为读取位置，缓存搬移不制造观察；相同来源版本的缓存别名归一，同字节但不同原始来源保留不同消息/元素。`read_source`必须显式收到source_id，不能默认用内容SHA代替。
2. **基线角色与实际初始化同时核验。** 唯一baseline角色必须与baseline_source、首个输入一致；snapshot不能冒充它。baseline仍保存全部RIB时点观察，没有从Resource输入删除。完整Peer表和非空基线元素实际保存后，二阶段回放数量必须等于该源元素回执，才允许完成。
3. **必要回执在发布之前。** `execution.json`先以`ready`状态写入并fsync；其`publication_authority`指向PG `domeye.runs`。PG是完成状态唯一权威，文件本身不宣布已发布。写回执失败只能得到failed候选，查询不放行。提交响应错误时重新读取权威状态；若确认complete，不再生成failed回执；无法确认时保留unknown，不伪称失败或成功。没有建设自动重试/outbox/断点恢复。

当时流水线为：完整参考整行与MRT观察入湖 → 完整源EOF/计数回执 → 固定观察快照 → 全UPDATE端点盘点 → 显式计算映射 → 从同版已保存观察回放 → 状态/必要回执导出 → PG完成登记。回放不再次打开或解析MRT。`replay_io.py`是当时的有限内部接口，candidate只供该次离线生产使用；外部scan/query仍拒绝candidate。当前直接批次入口不再等待此整文件回放流程，来源身份、端点歧义和未知状态边界仍须保留。

全输入映射规则为 `full-input-unique-calculation-endpoint/v1`：对基线原Peer IP/ASN，基线原Peer条目必须唯一；全部UPDATE来源的本地IP/ASN/interface组合也必须唯一且字段齐全，才生成计算基线映射。保存基线Peer来源引用、全部候选端点、各端点见证消息/数量和输入范围。多本地端点、基线冲突或无UPDATE分别记录受限原因，不任选一个、不合并Session、不以一次新观察恢复全表。此映射用于声明计算过程，不升级原始Peer事实或实际Session连续性。

### 1. 身份、布局与唯一成功点

`plan_id` 固定归一化输入有序清单、原 source_id/origin_uri/SHA/size/role、collector/窗口、解析和 interpretation/结构/规则/引用解释版本、代码摘要及下述 resolved_format/options。新机制的 `run_id` 表示这一固定候选；每次进程为新 invocation，每次完整文件尝试为独立 attempt。同一新 run 可在相同计划下恢复已 checkpoint 文件；原 726 failed run 不迁移、不改状态、不复用其部分行。已核对302项范围（277旧结束回执、1坏当前源、13未进入MRT、11引用）保留全部原件/旧候选，旧 checkpoint 可直接复用数为0；这是恢复证据不足，不表示277份原件都坏。

一个 catalog 使用**唯一固定 DATA_PATH**，恢复和所有 attempt 精确核对同一根，禁止 OVERRIDE、每 attempt 换 catalog 根或创建302个catalog。Git 外每 attempt 的 staging/临时/日志目录独立，不能将其与 catalog 数据根混同。物理观察表的每行携带内部 attempt 身份；自然 message_id/event_id/path_key 和原 bytes 不改变。所有文件内批量只属于当前 attempt，末尾强制 flush。path_keys 按 attempt 隔离，失败临时索引不得抑制新 attempt 写入。

完整耗尽迭代器、来源 SHA/实体戳/EOF/CRC、角色/时间约束、实际持久化记录顺序/元素序/全表计数/typed摘要/FK 核验通过后，固定该 attempt 的 DuckLake snapshot 和数据文件清单，落盘不可变 prepared manifest（含 fsync 文件及父目录）。**持锁会话的单次 PG checkpoint COMMIT** 原子选择该 attempt、登记前驱 checkpoint digest 和连续输入 ordinal，才算文件成功。prepared 或部分提交都不是 checkpoint；中断当前文件用新 attempt 整文件重做，不修补或自动收编 orphan。已完成文件不重新解析；恢复完整性检查与解析次数分别计量。

数据文件清单须由受控写入提交记录、table/file ID、固定快照可见性及实际 attempt 行归属核验得出，绑定路径、大小、文件 SHA、表行范围及摘要；**不能仅假定 begin_snapshot 等于一个输入文件**。发现跨 attempt 混批/归属不符则拒绝 checkpoint。本片禁止 compaction/GC/后台整理改写或删除被引用的数据文件，不直接改 catalog 内部表来修复归属。

最后文件 checkpoint 与整批 observation seal 分开：seal 将有序 `(source,attempt,ordinal,checkpoint_digest)` 选择清单及必要的全局 path 代表索引固定在 DuckLake，绑定精确 seal snapshot/digest，再经持锁会话 PG 事务登记。不复制全部消息/元素正文；未选中的 attempt 永不进入逻辑输出。同 path_key 的完整typed摘要必须一致，代表索引按固定来源序选原行，保存在 DuckLake，不在 PG 存历史正文。来源全表计数与逻辑 paths 唯一数分别核对，不累加重复字典冒充唯一数。

### 2. 所有者与失锁提交（独立意见 2.1 闭合）

采用**单一持锁 PG 会话**机制，不再同时建设 generation fencing。协调父进程创建专用 PG 会话取得 run advisory lock；checkpoint、seal、接管后的 run 状态/失败状态变更只通过这一个会话执行。事务和锁会话不分离，不交给连接池，不透明重连；不得沿用旧 Store.fail 的新连接补写失败路径。

一旦锁会话断开或锁所有权不能确认，该 invocation 永久撤销提交权：终止后续选择/状态写、请求停止子进程，只可通过新的只读连接查询已提交事实及记录 Git 外诊断。即使 A 进程仍活着，也不能通过另一个写连接重取锁后继续旧 invocation。恢复必须显式创建新 invocation 并独立取得锁。会话正常结束也只在所有写流程关闭后释放锁；不允许“暂时解锁后继续写”。

若父持锁、子进程解析/写湖数据，只有父可选择 attempt。父失效后子进程晚到的数据只属其唯一 attempt 的 orphan，不能 checkpoint/seal/改 run 状态；新父不得收编这份未登记尝试。另一个 invocation 接管不改变旧 attempt 的选择资格。湖数据提交与 PG 选择不是分布式原子事务；先落数据、后唯一权威登记。

COMMIT 响应不明时，只读查精确 checkpoint/seal 身份判定已成功/未成功/冲突；失锁的旧 invocation 无权因此补写。新 invocation 接管后才能在完整核验和持锁条件下继续。必须测试：A 锁连接断开但进程仍存活，B 取得锁接管，A 迟到 checkpoint、seal、failed 三种写均被拒绝，B 的状态不被覆盖；不能仅测两进程同时抢锁。

### 3. 引用解析格式与路径别名（独立意见 2.2 闭合）

现 references.rows 先按 ZIP magic 选择工作簿分支，否则 `.csv` 后缀选 CSV，其余选 JSON。M2 在计划绑定和每次恢复/读取前解析同一规则的 `resolved_format`（ooxml_zip/csv/json），连同影响 typed 解释的固定 options/version 纳入 plan 和文件 checkpoint。显式声明与实际分支不一致即拒绝，不尝试另一分支“修复”。格式识别不是内容有效性证明，后续解码仍可失败。

选项包括：CSV 的 UTF-8/newline、固定 excel dialect（delimiter/quotechar/doublequote/escapechar/skipinitialspace）及 strict、BOM/物理行/空白行规则；JSON 的 UTF-8、顶层对象约束和保留重复键/顺序的 object_pairs_hook 规则；工作簿的 read_only/data_only=false、sheet/行顺序及单元格类型/值序列化规则。解析代码/依赖版本也固定，资源上限另列，不把格式变化掩盖成路径别名。

同 SHA、同 resolved_format/options 的缓存别名可替换读取位置，不创造新 source 身份或重复观察。相同 SHA 的 `.json` 与 `.csv` 若走不同分支则在复用前拒绝；需要另一解释时必须新计划，不能部分来源复用旧解释。一个计划内同 source_id 的别名也先核对格式/options一致再去重。保留 reference-rows 的原 source_id、重复键/行、顺序、原字段类型及 effective_time_state=unknown。
