## 2. 一份 publication 绑定什么

### 2.1 最小记录

业务 publication 是一份不可变的**明确依赖集合和可用性声明**。它可以引用不同 run、不同 catalog、不同 snapshot，不能使用“每表最新”生成隐式依赖集合。建议首版仅保存四类 PG 控制记录；这里描述字段合同，不是 SQL 迁移：

| 记录 | 最小字段与约束 |
| --- | --- |
| `publications` | `publication_id`、`manifest_sha256`、`manifest_uri`、`contract_version`、`intent`、`profile_id/profile_digest`、`quality_receipt`、`state`、`created_at`。ID 绑定规范化清单摘要；创建时间不参与内容身份；同 ID 不同摘要拒绝 |
| `publication_components` | `(publication_id,component_key)` 唯一；绑定下表的 DatasetBinding 和可用性。没有产物时 binding=null，仍必须声明缺项 |
| `query_builds` | `build_id`、`publication_id`（发布时绑定）、`projection_version`、`input_binding_digest`、各副本计数／内容摘要／关联检查、`ready`。副本不得作为另一份结果权威 |
| `publication_heads` | `selector_key`、`publication_id`、`build_id`、`generation`；一个事务更新，一个 selector 对应一个明确发布配置。完整与分模块选择不共用同一 head |

为避免身份循环，先对 profile、component bindings 和质量声明计算 `input_binding_digest`，再构建 build；最终 manifest 引用 build_id、投影版本和输出摘要，计算 publication_id，提交时将 build 绑定到该 P。build 的输入摘要不包含最终 P、build输出或 created_at，输出摘要也不含回填的 P。

清单存于 Git 外；运行时凭据不进入身份。`catalog_ref` 是受控目录的持久身份（物理数据库实例身份＋metadata schema），由部署绑定解析为连接，不能只写可漂移的 DSN 别名。数据库搬迁时须保存原身份和经过核验的位置映射，不另造一个同名 catalog 冒充原版本。

每个非空 `DatasetBinding` 至少具有：

| 字段组 | 明确内容 |
| --- | --- |
| 数据定位 | `component_key/dataset_id`、`catalog_ref`、`schema_name/table_set`、`run_id`、`snapshot`、`schema_version`；旧文件源保留原 `source_version`，历史导入增加新的 import dataset 身份 |
| 执行与规则 | 固定代码提交及实际 code_digest、依赖锁／执行身份摘要、算法与规则版本、参数摘要、decoder/projection/reference 解释版本；历史未知值为 null＋原因，不能替成导入器版本 |
| 输入与参考 | 有序 InputBinding 集合、ReferenceBinding 集合及 manifest/receipt 摘要；真实 origin_uri、SHA256、source_id、原 source_role；另列 calculation_role、window_role，不修改上游 role |
| 范围 | collector 或明确 collector 集合、AFI/SAFI、对象范围、result_window、input_window、warmup/comparison_window、实际时点、data_through、业务时区、时间精度、cohort（如适用） |
| 质量与完整资格 | complete 登记、ready 文件身份、期望／实际消息和元素数、各输出表期望／实际行数、拒绝／缺口回执、质量规则与决定、来源复验结果；独立人工审核另有引用，不用 complete 代替 |
| 解释 | `origin_kind=historical_import/new_computation`、原质量限制、单位、稀疏语义、初态依据、旧连续态等价性、已知错误／不可比较项 |

InputBinding 同时保存 `(catalog_ref,run,snapshot,source_id)`，源唯一身份仍按真实来源规则核验；相同原件在两个 run 的别名必须列明，两者原 role 可不同。重复观察不是内容去重对象；选择同一 source 的重复别名是否重复计算由模块已有输入合同决定，publication 不能私自合并其结果。

ReferenceBinding 保存参考原件 SHA/URI、规范化 dataset/run/snapshot、解释规则、选择行规则、历史适用性、以及 Reader 资格所需锚点。**全局 as_entity 的承载 run collector 可以不同于业务 collector**，原 provenance 完整保留；资格锚点的 RIB 不进入参考业务范围，也不当成计算基线。业务 RIB/UPDATE 必须匹配计算 scope；国家映射等参考是否适用按各依赖的规则判断。禁止 publication 层强制所有 collector 相同，亦禁止完全忽略范围兼容。待审 Feature 多源代码目前有 reference collector 相等校验，与此补充合同可能不符，须待其独立复核修订后绑定，不在这里复制修改。

例如 default catalog 的 Resource snapshot=42 和 `fl_F` 的 Feature snapshot=7 可以同属 P；两者都为 42 也不能说明同版。P 应检查各自完成资格、所需输入范围和引用一致性，而不是 `resource.snapshot == feature.snapshot`。

国家模块只交付固定计算制品和完整 component contract；业务 publication、PG可见指针及跨模块选择协议由本文一处定义，不建立第二套国家业务发布体系。历史国家原 publication 仅作为来源身份保留。国家作者任务 `01a09705-eb1d-79d2-b63f-fd368d8a653f` 后续定稿时，应提供每事件的基线绑定（允许事件间不同）、输入顺序与窗口、输出版本、质量及关联键，供本合同引用；当前不猜测其尚未定稿的字段布局。

### 2.2 事件与证据关联

用显式关联表／清单边固定以下关系，每条边都引用 component_key 和该 component 的对象键；不要求所有产物放在一张表：

`publication → 事件修订 → 详情／证据 → cohort → 时序／路径 → ASN 查询`

- 事件键为 `(component_key,incident_id,revision)`；历史行键另为 `(source_freeze_id,原schema,原table,原row_key或导出序号)`。事件时间＋类型＋ASN 不是主键；同名事件、重复行、同日新旧计算都不能合并。
- 详情绑定原事实记录和解释版本；Detection 的 `sequence/record_kind` 不能直接当不同事件计数，生命周期多 revision 的折叠规则单列版本。列表选定 revision 后详情保持该 revision；保留原 `event_info/detail_url/legacy_json`，不能只存摘要。
- `cohort_id` 绑定成员数据集、纳入规则、分母与冻结时点；`event_metric_id/event_as_path_id/event_read_model_id` 分别保存。路径记录引用事件、cohort、前缀、原 Peer/VP、路径字典版本和观测时点；AS_SET 原文及未知起源不转为强制 ASN。
- ASN 下钻请求携带 P、事件修订、cohort、ASN 和原窗口；先验证成员资格。cohort 未取得时返回 `membership_unknown`，不得把普通 Feature 请求200包装为同版事件证据。可明确读取同 P 的普通 ASN 窗口特征，但返回 `relation=same_window_only`，不能冒充 cohort 证据。
- 历史国家制品原有 publication/revision/cohort 全部保留为 `source_*` 身份；外层 P 是导入发布，不能覆盖原 publication 字段后声称原生同版。兼容层有明确的外层 P↔原发布映射。
- 边缺失分 `not_produced`、`not_retained`、`ambiguous_reference`、`incompatible_scope`；不能生成空关联证明没有事件或没有受影响 ASN。跨 publication 对比仅通过显式左右发布查询，不通过普通详情接边。

### 2.3 国家新增前缀指标的版本语义

协调任务已明确的新版本定义：`new_visible_*` 是“本事件曾明确纳入的新前缀集合的当前可见量”；`new_cumulative_*` 是曾纳入前缀的累计并集。不要求当前 origin 仍映射该国，不能将前者称为当前国家归属资源。component contract 必须保留 `membership_basis`、`first_qualified_ref`、原路径与 origin refs，并绑定指标定义版本、单位、观测时点与事件窗口。

验收反例：前缀首次以明确证据纳入事件，随后 origin 映射到其他国家但仍可见；新版本的 new_visible 仍按事件已纳入集合统计，累计集合亦不因此删除该前缀。具体去重粒度和各单位字段等待国家 component 定稿，不以字段前缀相同猜测。历史15轨跨国语义为 Unknown，导入原样保留 `track_definitions` 与原算法/质量信息，不标为本次新算法，不与新版本无条件合并时序。

## 3. 完成、可用与覆盖分开

建议使用独立维度，避免一个 `status=complete` 包办所有语义：

| 维度 | 首版值／含义 |
| --- | --- |
| 发布生命周期 | candidate → published；失败停留不可见候选并保留 failure 原因。模块本身原有 failed 不改写 |
| 发布意图 | `full_business` 或 `module_scoped` 或 `historical_import`；profile 预先列必需模块／表／关系／查询能力，不允许结果出来后缩小必需集合凑 full |
| 组件可用性 | available、known_empty、unavailable；unavailable 必带 reason，如 not_produced/not_configured/not_retained/validation_failed/source_missing |
| 覆盖 | complete_within_declared_scope、sparse、unknown、gapped；complete 只指声明范围与口径，不表示全网或 Session 连续 |
| 点或单元格 | observed_value、observed_zero、calculated_value、calculated_zero、unknown、not_applicable；计算值必须带basis/rule/assumptions，不冒充直接观测；缺项不返回零值 |

known_empty 要求必需输入、对象枚举／窗口、完整输出资格和空结果验证全部通过；“表存在而没有行”“D 没有新开始国家事件”“224–310 空 ASN 页”都不满足该证明。Feature `row_presence/resource_status`、source_receipts 的 gaps/quality 必须保留；无变化未落行只能标为按规则稀疏，是否可延续旧值要另有状态证据，不能默认补0或前向填充。

完整业务发布 profile 至少要求观察/状态、Resource、Feature、Detection 六类及详情、中间结果保留和 Country 约定输出闭合；哪些 Country 输出与趋势构成首轮必需项须在实施前固定（第 8 节）。未决或缺失时只允许 module_scoped，不选 full head。没有自然事件的类型可以有 known_empty，但其算法 fixture 验收仍须独立通过。证据不足的某指标可发布明确 Unknown，前提是 profile 允许该项限制，不能对必需关联损坏作这种降级。

历史导入的完整含义是**冻结清单全部按原样迁入，包括隔离与缺项**，不等于历史业务全覆盖。55 日 Core available 和 4 日 failed 可同在历史 P；失败日 business payload=null，详情也受门禁。全历史 PG 内容未冻结时不能声明该导入 profile 完整。D 旧历史和 D 新计算必须分别 publication，默认选择须有明确 intent，不能让“最新 D”覆盖旧引用。

## 4. 首轮持久化与原子可见协议

以下是待实现协议，不声称当前各 store 已提供业务发布或断电恢复：

1. 离线发布器接收固定的 publication 清单和 profile，依照显式模块 Reader 读取 complete 结果。所有必需来源、scope、表结构、引用、双计数和质量决定先验证；拒绝 fixture 执行身份进入真实发布。
2. 核实引用的持久文件实际存在、关闭写入、大小／SHA／逻辑行摘要匹配；对本次写入的文件与父目录做持久化确认。DuckLake 文件定位通过固定 catalog snapshot 取得；Domeye 保存验证回执及其摘要，不另造一套替代 DuckLake 的文件目录。首版采用单写入者、封存后不修改及被引用版本不清理的约束；无法确保引用文件留存则拒绝发布。
3. 在候选 build 下离线生成 PG 查询副本，所有行以 build_id 隔离；固定输入快照、投影代码、单位和兼容规则。核对 counts、保留重复行的内容摘要、引用连通、查询聚合及分页样本，生成 ready build；构建期间 Web 不可发现该 build。
4. 在 Git 外持久目录封存 manifest 和质量回执（临时文件→关闭/持久化→原子命名→目录持久化）。清单包含固定 component bindings、build 输入／输出摘要，不包含可漂移的 latest 表达式。此时仍只是候选。
5. **一个 PG 事务**锁定目标 selector 的 head，核对期望 generation、publication/manifest 身份及 ready build 的 publication/input digest，写入发布和组件记录并更新 head `(P,build,generation+1)`。模块 complete 状态在事务中复核；若绑定发生漂移，拒绝。事务提交是唯一业务可见点；不得先改日期目录再逐组件更新 head。
6. Web 首次发现只读取 head 一次，返回 P＋build 的查询令牌；后续所有分页、详情与关联请求固定该令牌。读取器以只读事务核对 published 和 build 就绪，所有 SQL 限定 build_id，历史扫描指定各自 catalog/snapshot。坏版本明确不可用，不回退旧版，不触发修复／建索引／解析。

首轮不需要跨 catalog 分布式事务：发布前封存的组件均不可变，PG 事务只选择已经就绪的整套引用。若有人可以并发修改／清理绑定文件，该前提不成立；必须先建立封存保护，不能以“已算SHA”掩盖校验后变化。

| 失败位置 | 首轮外部可见结果 |
| --- | --- |
| 文件未完成、输入校验失败、build 半写或 manifest 未封存 | 旧 head 不变，candidate 留证，不可通过显式 P 读取 |
| PG 可见事务回滚／generation 冲突 | 旧 head 不变；保留候选，不自动换目标或回退覆盖 |
| PG 提交确认未知 | 暂停并人工只读核对 P/摘要/head；不得自动重放写入或直接宣称失败。已提交则固定 P 查询；未提交保留候选 |
| 发布后文件／副本损坏 | 固定 P 不可用并明确故障，不静默拼接别版；重新构建须另行离线授权 |

失败重算采用新 run；没有 checkpoint 续跑、outbox 或自动补偿。同 ID＋同摘要再次请求只能确认现存发布，不重选曾经被后续发布替换的 head。同 ID＋异内容拒绝。保留行数／字节／内存／磁盘保护；离线计算不设置总运行时长上限。查询可有独立有界预算，超限返回 unavailable，不能截断后装作完整总数。

## 5. 共享查询 Interface 与消费者 mapping

### 5.1 小而完整的入口

建议放在现有 `backend/services` 下的业务查询模块；HTTP Resource 继续通过它组装既有响应。内部复用现有模块 Reader 和 PG 副本 Adapter；首版只实现真实需要的几类 Adapter，不提供任意 SQL、任意插件注册或“查询所有表”的万能入口。

```text
发现(selector, intent, 范围) -> 发布令牌(P, build_id, profile_digest) 与逐组件可用性
解析引用(令牌, 原引用, 可选原来源版本) -> 固定对象键或明确歧义/缺项
查询(令牌, 有类型的查询请求) -> 数据、分页、可用性、单位、范围、来源绑定
```

“有类型”是有限的请求联合：Core日概况/原记录、RIB快照/观察/ASN、事件列表/详情/证据、特征序列/档案/排行/并发中断、国家概览/序列/成员/路径/审计/趋势、P0状态/指标/质量。每个请求显式窗口、筛选、排序及字段集合；禁止把调用方传入的表名或 catalog 当 SQL 使用。内部统一处理引用、身份、缺口和预算，保持一处修复能作用于全部消费者。

返回 envelope 始终携带 P、build、使用的 component keys、原来源版本、scope、单位／定义版本、availability/reasons、limitations。数据为空与不可用分别表示。未知 P、未发布 P、错误 build、越界窗口、歧义引用、缺失 capability、来源损坏有独立错误码；具体 HTTP 状态与 envelope 变更在后续实现同步 OpenAPI、后端测试、`make api-types` 及 `src/api`，本次不修改 HTTP 合同。

不让每个 endpoint 单独 discover。旧无版本 URL 仅在入口解析一次明确的兼容默认，响应返回令牌；后续请求和 URL 保持版本。需要新增发布/cohort 透传的 ASN 跨页属于阶段 4 合同变更；在完成前只能称旧同窗口特征。损坏不可触发 EventDetailPage 的旧事实成功回退，保留其“明确未配置才尝试下一展示路径”的区分。

### 5.4 时间、分页与旧引用

- 内部时间采用带时区半开 `[start,end)`；D 为 `[2026-02-27T16:00:00Z,2026-02-28T16:00:00Z)`，数据档 Asia/Shanghai 不变。保留原无时区文本、存储精度和解释依据，微秒不能截成秒。
- `feature_asn._end_exclusive` 对 timestamp(0) 旧含端点请求加1秒。仅该秒级旧合同可如此转换；新半开请求不能再加1秒。旧 `country_service/asn_service` 前窗起点是 `start-(end-start)`，SQL current 为 `t>=start`、总范围 `t<=end`。兼容请求须先按旧 start/end 算 previous_start，再转换当前 end 为 end+1秒，前窗仍 `[previous_start,start)`，不能按转换后长度倒推而多取一秒。新原生请求可用严格等长前窗，但必须另有语义版本和对照差异。
- 普通档案现有最大24小时、事件单ASN最大45天守卫按旧请求语义保留；不要因转换后多1秒误拒绝。跨月／cutoff 先冻结实际切片；事件窗口不强加普通前窗。基线查询 `get_as_baseline` 原“事件前5分钟不含”单独保留，不能统一加1秒后吞掉排除规则。

- 每个集合有固定总排序：既有业务排序＋稳定原行键／导出序号作为平局键；总数和页数据共用 build、filter digest。当前 page/page_size 可继续，不能翻页发现新 head；游标若使用，绑定 P/build/filter/sort/last_key，不允许跨版本复用。通用国家 `_page` 当前限制 page_size≤60并裁剪页码，兼容 Adapter 保留；其他入口按各自现合同，不统一套60。

### 5.5 查询副本可重建

历史 Parquet／原始保留副本和 publication manifest 是重建输入；PG查询表按 build_id 存 `core_days/records`、`events/details/ref_aliases`、`feature_points/profiles`、`country_members/series/path_relations` 等实际用到的投影，首片仅建所需两类。表名为建议，不是本轮建表。完整原行放历史层，不把未展示字段丢掉。

build 记录投影代码/参数、输入 component 摘要、行数及逻辑内容摘要；重建相同投影应逻辑一致（不要求 Parquet 物理字节相同）。原 manifest 永不改写；重建 build 另记 `rebuild_of`，必须匹配原 manifest 中的输入摘要、投影版本和逻辑输出摘要，才能登记为该 P 的等价查询副本。新 build 离线核验后才能原子选择；已发出令牌仍固定旧 build，不在翻页中途切换。若投影语义或逻辑输出改变则建立新 publication，不能借“重建索引”悄改数字。Web 不做重建，原来那些动态回退分支不得成为新 Adapter 的兜底数据源。

## 6. 历史冻结与无损分批迁入

这里只设计未来获授权后的只读获取方式；本次未运行导出／导入。0B的文件摘要和37表样本是定位依据，不是数据库全历史 identity。

### 6.1 冻结单位

PG历史建议在同一只读 repeatable-read 快照内取得 schema、约束、实际表/切片、总数和所有分批行；并行导出如有必要须显式共享同一导出快照且持有者存活，否则不是一致冻结。记录实例身份、快照标识、获取时刻、事务与时区／编码设置、导出工具版本；快照 token 不是长期内容身份，长期身份来自封存导出、schema、逐块与整表内容摘要。采用一个冻结源再离线分批导入，不按不同日期开独立事务冒充同一全库快照。

若无法取得统一快照，可将多个独立冻结源分别声明，但涉及总表→详情、跨表聚合不能标为一致完整。跨 PG 与文件没有天然事务：已不可变的 Core、国家、INFO文件可分别绑定其原版本；若文件在变，须取得不再改写的副本／发布版本并复核前后实体与摘要。不以 mtime 相近宣称跨源同时刻。现有 release `20260717T124354Z` 也不能证明当前库之后无改动。

文件获取未来只读复制原件并封存，保留 SQLite 原文件、manifest/诊断、压缩 JSON/JSONL、CSV/XLSX等原字节；源 URI/SHA/版本与导入目标分开。既有目录保持不动，原件不删除。冻结导出大小、内存、磁盘预算先确认；长运行采用持续进度观察，不设总时长强制终止。

### 6.2 每行保存合同

导入包元数据保存原schema／字段顺序／大小写／PG类型和精度／nullable／默认值／约束／数组维度及下界、原时间单位与时区语义；保留源冻结版本、表、主键（若确有）和块/行序号。0B仅字段类型不足以证明真实主键，须在未来冻结时获取，不能照建表源码推断现场约束。

- 每原表有 typed Parquet 映射和可逆原值表示；原 numeric 不经 float，超出目标精度时保留有类型十进制文本；interval 保留月/日/微秒分量，不能压成总秒而丢“月”。无时区 timestamp 保存原值，UTC解释列独立且允许 Unknown。
- SQL NULL、JSON null、空字符串、空数组、数组内 null、文本 `"null"` 分别保留；原 text 中编码的数组／JSON仍是 text，另建可选解析投影，不能执行 eval。JSONB 的原存储已不保留对象键顺序，导入不能声称恢复写入前原JSON字节；保留其可导出的值和类型。
- 字段未存在和字段存在但 null 分开；新增目标列不能默认0覆盖缺项。整数大于 JavaScript安全范围在查询序列化时用无损表示，HTTP变化另行维护。
- 不用行内容 hash 当唯一主键去重。无PK表使用固定导出文件的块/行序号标识 occurrence，同时记录内容摘要和重复次数；CTID若记录只作同快照定位，不作跨冻结稳定身份。稳定分页用封存导出顺序，重新冻结是新 source_freeze_id。
- `event_table` 的 state/judge/notify、详情过滤字段、原比例、原路径与不被当前页面显示的信息全部迁入；不因历史责任字段有偏差删除数据，在解释层绑定限制。
