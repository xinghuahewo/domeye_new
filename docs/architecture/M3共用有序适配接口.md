# M3 共用有序适配接口（第一实施片）

本片实现共用边界与 Gap 分类，并以人工 Reader 流验证；尚未接入 Replay、Feature、Detection、Country、Resource，也没有实现范围索引、业务资格存储或独立 writer/finish。适配器通过不等于 M3 完工或真实数据准入。

基线为 M2 `27e6f7bbc1ec1bc970dde990252b4d7d896b3608`。语义依据是父任务接受的 M3 合同 SHA-256 `d4c479a2dcbe22a94620f0f8bd6fc6fb2e35dab05cebf46e20ac1292f7d9327f`，含 Feature ordinary/IR 与 Detection 双向 LOCAL 依赖修订；固定接缝补充 SHA-256 `4bd7c9d62678506dfb77c5659f3904e470d7238cc6107225eba9d60fb287e2b9`。本片不修改这两份 Git 外材料。

## 公共导入与入口

```python
from data_pipeline.observations.ordered import ordered, binding_from_reader
from data_pipeline.observations.ordered_contract import (
    MessageBoundary, Element, SourceStart, SourceEnd, SourceQuality,
)

# reader 必须是明确 profile='observation'、run_id、expected_snapshot 的既有 Reader。
# reader.sources 可以是完整清单的有序子集，排名始终来自完整清单。
binding = binding_from_reader(reader)
for item in ordered(reader):
    if isinstance(item, MessageBoundary):
        # 在本消息元素前消费一次边界；gap 与真实 STATE/EOR 分开判断。
        consume_boundary(item)
    elif isinstance(item, Element):
        consume_existing_element(item.raw)
    elif isinstance(item, SourceQuality):
        retain_source_quality(item)
    elif isinstance(item, SourceStart):
        begin_source(item)
    elif isinstance(item, SourceEnd):
        finish_source_coverage(item)
```

示例中的业务函数为消费方待接线责任，当前仓库不提供这些函数。既有 M2 流仍是 `consumer.SourceStart / MessageBatch / SourceEnd`，没有新增或假定 M2 `StreamFrame`。

`ordered(reader)` 使用 `reader.stream()` 的固定选择、读取前封印与来源尾核验。`binding_from_reader` 只取固定元数据，不替代这些动态核验。低层 `adapt(stream, binding, selected_sources=None)` 用于人工测试及已有受控桥接：只校验流合同，不连接数据库，因此手工构造 InputBinding 和流不能证明 M2 封存资格。生产消费方应调用 `ordered(reader)`。

## 固定类型与身份

类型定义位于 `observations/ordered_contract.py`，适配与 M1 JSON 校验位于 `observations/ordered.py`。版本为 `ordered-observation/v1` 与 `payload-gap/v1`。

| 类型 | 公开字段与含义 |
|---|---|
| InputBinding | collector、observation_run、seal_snapshot、plan_id、seal_id、seal_digest、完整 MRT SourceBinding 序列、profile 与三个合同版本；binding_id 为规范元数据 SHA256 |
| SourceBinding | source_id、content_sha256、role、checkpoint_digest、messages/elements/decoded/rejected/unsupported 预期计数；不暴露物理 attempt |
| MessagePosition | source_rank、record，均非负整数；sort_key=(rank,record,0,0) |
| ElementPosition | message、ordinal；sort_key=(rank,record,1,ordinal)，不用负 ordinal；与消息位置比较使用 sort_key |
| MessageBoundary | binding_ref、position、raw_time、完整原 raw 字典、强类型 interpretation、gap 或 None |
| Element | binding_ref、position、完整原 raw 字典；原 bytes、None、0、ADDPATH 标志、AS_PATH 文本与全部字段不变 |
| SourceStart / SourceEnd | binding_ref、完整序 source_rank、原 consumer 对象；End 另含 ParseCounts(decoded,rejected,unsupported,gaps) |
| SourceQuality | binding_ref、source_rank、原 quality 字典；没有消息位置，不捏造 record，不重复派生 Gap |
| Gap | gap_id、binding_ref、message_id、position、raw_time、scope、direction、parse_status、reason_code、interpretation_digest、raw_ref、header、完整 interpretation、rule_version |

`InputBinding.sources` 使用 M2 已封存 manifest 的完整 inputs 原序，保留 baseline/snapshot/update 原角色；baseline_source 必须对应唯一首位 baseline，update_sources 仅核对 update 角色子序列，不能用它重建全部来源。reference checkpoint 的 ordinal 不参与排名。子集例如只选完整清单中的第 2 个来源，其 source_rank 仍为 1。binding_id 仍覆盖完整链，不因消费子集重编号。具体模块必须另行记录自己实际选择和完成的来源，不能仅凭同一 binding_id 宣称全链已消费。

M2 `plan_for` 已调用 `normalized_inputs`，按来源身份首次出现顺序去除同源同角色的本地缓存路径别名；封存 manifest 的 inputs 已是该规范清单。适配器使用此清单及对应 checkpoint 顺序，不再次去重或读取原路径。封存清单重复身份（即使声称同角色路径别名）、多角色冲突、缺失/重复/乱序 MRT checkpoint 都拒绝；消费者不能传原始未规范别名清单替代封存清单。跨 run 的 Feature baseline/snapshot 别名对应由消费层保存，单次 ordered 调用不拼接多个 run。

Gap 自然身份绑定规则版本、原 source/content/record/offset/length/raw_digest 和规范 interpretation 摘要；摘要只排除本地 source_path 定位提示。不同原观察不合并，同一选中观察不因批切法重复通知。seal 或选择改变时 binding_ref 改变，即使 Gap 自然 ID 相同也不能混用版本。`metadata_json` 提供 Binding/Gap 等元数据的稳定 JSON，枚举为明确字符串；它不是原始 bytes 观察的通用序列化器。本片不新增数据库表或持久化格式。

## 顺序、保真与完成

适配器逐批归并两组已有序数组，持有当前批与一条当前消息上下文，不收集整个来源。每消息边界先于其任何元素；同批较早消息的元素必须先于后续 Gap。消息头与元素跨批分开时仍只发一次边界。零元素消息、正常空 UPDATE、STATE、EOR、KEEPALIVE 和来源质量均保留。原始字典及附属列表不复制、不改写；共享消费方必须只读使用，私有算法需修改时自行复制。

顺序依据数值 rank/record/ordinal，不按 epoch、微秒、文件名或文本 ID 排序；原时间倒退和同秒精度原样保留。固定版本的字段集合及标量类型、消息/元素身份引用、连续物理位置、连续 ordinal、来源身份和所有 SourceEnd 计数均校验。原始内容摘要只验证格式与绑定；不打开原件重新计算，也不替代 M2 完整性审计。真实 STATE 保留 raw.kind/old_state/new_state，EOR 保留 raw.eor，不生成伪 A/W 或状态变化。

只有收到原 M2 SourceEnd 并对账固定来源计数、三种 parse 分类后，才允许发出本层 SourceEnd；最后一个选中来源的 End 还须等待上游正常耗尽且清理成功。关闭迭代器会关闭上游；早停、缺 End、尾核验或最终清理失败都不能得到最终 End。一个来源 End 只证明该来源，不证明剩余来源或业务已完成；整个调用成功必须正常耗尽。收到 End 的业务消费者仍须先保存自己的独立覆盖再生成业务完成回执。

## 缺口范围与业务责任

`decode_interpretation` 校验实际 `mrt-interpretation/v1` JSON 的精确字段、重复键、枚举、布尔值、整数范围、HeaderEvidence、FieldFailure、继续许可及完整外框。拒绝帧只接受既有 M1 isolate-payload 白名单；已知 unsupported 保留独立分类。未知版本/策略/原因、时间错误和引用冲突失败，不再 catch/continue。白名单在此固定版本明列，不扩展 M1 许可；未来 M1 合同变更需要明确更新并验证接口。

每条受限消息产生一个 Gap，不按 quality 诊断条数重复。仅可信 HeaderEvidence 决定方向/端点；不从 reason、顶层残留 peer 或错误 NLRI 片段猜测。scope.kind 为 received_endpoint、local_observation 或 collector_chain，direction 为 received/local/unknown。可信端点单列 peer_ip、peer_asn、local_ip、local_asn、interface；endpoint_afi 保留在原 header，不成为路由族限制。

所有 scope 的 route_families、prefixes、path_slots 均为 all_including_unseen。peer_asn_evidence 保留可信原 Peer ASN，供旧模块检查同 ASN 折叠依赖；原 Peer 未知时 unknown_peer_covers_unseen_asns 为真。unmapped_rib_overlap 始终 requires_dependency_check，不能据字面 unmapped 键排除可能重叠。session 始终 None。

LOCAL scope 不伪装 received 端点。canonical 可按已接受合同判 received 损失不适用，但 Feature 两 mode 与 Detection 仍须处理自己的 LOCAL/同 ASN/未来 prefix 依赖；适配器不提供“业务安全”标志，也不替各模块裁定资格。缺口不因当前命中为零而消失；后续恢复、范围索引、legacy 兼容、窗口/事件/revision 资格及 writer/finish 均为后续授权片。

## 上游清理与异常修订

在 snapshot 修复 `bfa7faf623640be4e9c5221700fd86aa4d33afb6` 上修复原独立审阅的清理 P2；不修改 Gap 类型、分类、身份或科学范围。

从适配器第一次推进起，参数转换、绑定校验、取得迭代器和消费均在同一保护范围；无论在哪一步失败，都尝试关闭已取得的迭代器与传入的可关闭 stream。两者是同一对象时只关闭一次；不同对象按迭代器、stream 顺序各尝试一次，一个失败不阻止另一个清理。各对象仍负责自己的内部资源，适配器不会猜测两个对象是否互相代理关闭。尚未推进的 Python 生成器调用 close 不会执行函数体，此时上游资源仍由调用方负责，不能以此宣称已被适配器接管。

已有主异常时，保留原异常对象、类型及回溯，附加 `exception.cleanup_errors` 元组保存原清理异常对象（已有记录继续保留）。调用方应将这些错误写入失败回执，不能只记录主异常文本。正常耗尽但清理失败时抛首个清理异常，并附全部 cleanup_errors，最后一个 SourceEnd 不发出。早停产生的 GeneratorExit 会被 Python close 吞掉，因此早停清理失败改为明确抛清理异常，GeneratorExit 保留在 cause；这不构成业务成功。适配器退出后再次 close 不重复关闭上游。先前来源 End 仅是已完成来源证明，不因后续失败倒改，也不能作为整次成功。

回归覆盖已启动临时目录资源遇非法子集、参数转换失败、iter 获取失败、主异常加清理异常、不同 iterator/stream 双清理、正常完成关闭失败、早停关闭失败、重复 close 和完整有序正向对照。原 snapshot 覆盖保留；原独立脚本中的两条“缺陷存在”断言保持原样，不将其通过称作修复验证。

## 受限 ET 时间兼容修订

在 `1e9942c4e00e35217334509ea3ac76c1e15f21c1` 上修复 M3 对实际 M2 原子受限行的误拒。M1 `_decode` 已独立读全 ET 微秒，但 payload 抛出明确受限异常时，`decode` 只提交 interpretation，原 message 顶层 microsecond 仍为 None；M2 checkpoint 原样保存它。原适配器错误要求顶层/header 始终相等，因此拒绝本来已合法封存的 ET 观察。

新规则只针对 mrt_type=17、已支持 BGP4MP subtype、kind=unsupported、带 FieldFailure 的许可 rejected 或 unsupported_nlri：顶层 None 时，以已校验的 header.microsecond 作为 Boundary/Gap 的 RawTime 微秒；不改 raw 字典。decoded 或无 FieldFailure 的普通 unsupported 不能套用此分支；非空顶层与 header 冲突、缺可信 ET 微秒、越界微秒、非 ET 携带微秒仍失败。正常 decoded ET 顶层/header 相等规则不变；合法原始字段及输出序不变，不从 payload 或诊断文本猜时间。

ordered-observation/v1、payload-gap/v1 类型和科学规则版本不变；这是实现错误修复。Gap 自然 ID 原本已绑定完整 interpretation（含可信微秒）及原始定位，因此既有合法结果的 ID/字段不变；新允许消费的原子受限行首次获得该规则下的结果。代码提交身份必须随修复更新，不能把旧失败运行标记成成功。

重算范围：M2 已封存原观察、原 interpretation、checkpoint 和 seal 无需重算或重写。被本误拒中断的 M3 候选需使用新代码、原固定 M2 seal 从头重做 M3 派生消费及后续受影响投影，不能沿用失败候选的完成状态。当前未接入的业务模块不因此自动具备资格，未受影响且原本完整通过的无此形态输入无需因本缺陷重跑观察生产。
