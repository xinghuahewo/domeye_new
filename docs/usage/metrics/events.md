# 事件数量与生命周期

事件数量、开始异常的唯一对象数、某时点的并发数量和事件修订数是不同指标。结束时间是否记录与检测事件状态分开解释：当前检测器的 AS／前缀事件显式 `e_time = NULL` 表示尚未触发恢复条件；未知来源的历史记录不能直接套用这一语义。

## 六类业务异常

| 事件类型 | 当前结果描述什么 | 解释边界 |
| --- | --- | --- |
| 前缀中断 `prefix_outage` | 相应观察集合中的前缀可见性异常 | 不直接证明实际转发断网；历史 AS 归属存在偏差 |
| AS 中断 `as_outage` | 计算总体内达到相应条件的中断前缀异常 | 分母是该计算的前缀总体，不是用户数 |
| 国家中断 `country_outage` | 固定运行范围内异常 ASN 变化形成的事件 | 不等于全国实际断网；后续增强观测与原事件记录分别解释 |
| 前缀劫持候选 `hijack` | MOAS 等现象经规则筛选形成的候选 | 多起源现象本身不等于劫持；不能强行补出单一攻击／受害角色 |
| 子前缀劫持候选 `sub_hijack` | 父、子前缀及起源关系经规则筛选的候选 | 父子起源可能为集合，不能任意选一个 ASN |
| 路由泄漏候选 `leak` | 路径关系现象经筛选的候选 | 现象与事件不一一等价；历史记录缺少可靠结束生命周期 |

等级 `high`、`middle`、`low` 是已有规则与属性形成的分类，不是校准后的故障概率。记录中的描述、对象和角色保留其检测含义，不直接当作原因或责任结论。

## 统计哪个对象

| 数量 | 定义与单位 | 关键条件 |
| --- | --- | --- |
| 业务事件数 | 指定总体内按事件身份去重的事件数量，单位次 | 明确按“窗口内开始”“与窗口重叠”还是“某时点活动”选择 |
| 事件修订数 | 某事件或结果范围中的修订记录数，单位条 | 不替代事件数；多个修订不表示发生多次异常 |
| 规则判定／捕获数 | 内部规则调用或结果记录数量，单位条／次 | 不作为业务事件数量 |
| MOAS 现象数 | 按现象身份和窗口统计的多起源现象数 | 与派生劫持候选建立关联，避免重复计为独立异常 |
| 泄漏现象数／筛选通过数 | 分别统计现象与通过筛选的结果 | 未筛选、被过滤和通过是不同状态 |
| 中断前缀／ASN 数及比例 | 相应总体与时点下的对象数量及比例 | 窗口名单、时点量和峰值不能互换；历史存储比例可能需要重算 |
| 高风险事件数 | 同一事件总体中等级为 high 的数量 | 不代表真实严重故障总量 |

跨运行事件合并没有可默认采用的统一去重规则。对象和时间相近，不足以把两条记录合为同一次事件。

## Core 页的数量

| 字段 | 当前统计范围 |
| --- | --- |
| `overview.record_count` | 所选业务日和地址族范围内的留存异常记录数；不随列表的全部筛选条件变化 |
| `events.total` | 进一步按类型、等级、小时、搜索条件筛选后的记录数 |
| `events.distinct_prefixes` | 当前列表筛选范围内前缀中断对象的去重数 |
| `recorded_prefix_outage_starts_distinct` | 每小时开始的前缀中断对象去重数，不是该小时并发中断数量 |
| `event_trends` 中的 `recorded_event_starts` | 完成文件模式下，六类事件各自的窗口内开始数；按当前事件事实计数，修订不重复计次，只随业务日和地址族变化 |

同一前缀可在多个小时出现，因此小时唯一数相加不等于全日唯一前缀数。mixed 地址族记录可能同时纳入 IPv4 和 IPv6 两侧，两族事件数量不能直接相加。

## 现有档案与兼容曲线的数量

| 字段 | 实际含义 | 使用限制 |
| --- | --- | --- |
| `anomaly_count`、`high_risk_count` | 与某国家／ASN 关联的事件记录数及其中 high 数量 | 同一事件可关联多个对象，跨对象相加会重复 |
| `outage_count` | 采样瞬间处于检测中断区间的去重前缀／ASN 数，不是桶内开始次数 | 新合同按实际处理覆盖返回数值、`null` 与观测状态，详见下节；调用时核对实际响应合同 |

### 中断时序的覆盖合同

五个 `/api/v1/features/outages/*` 共用现有事件表读取与三分钟采样。请求采用业务时区的 `[start_time,end_time)`，单次最多 24 小时；一小时为 20 个采样点。读取所有与窗口重叠的当前事件，包含上月开始且尚未结束的事件，不再只查窗口月份视图。同一对象多条活动记录只计一次。前缀保留静态粗路由集合筛选，以及同前缀同开始时间优先取已记录结束的既有规则；该总体不是所有 CIDR，也不是国家事件峰值名单。

`outage-series/v2` 响应使用 `query / metadata / data`：元数据明确交付版本、采集器、实际数据起止、与请求相交的覆盖区间、采样秒数、单位及筛选总体。事件和覆盖信息来自同一个只读可重复读事务。可选 `version` 不匹配返回 409；这不是历史版本读取会话。

- `observed`：采样点已处理，活动区间满足 `s_time <= t < e_time`；显式空结束时间在连续覆盖内仍计入。确实没有中断对象时返回 `0`。
- `not_observed`：采样点在实际覆盖外或处理缺口内，值为 `null`。
- `unknown`：虽然采样点已处理，但仍活动的记录开始于本段连续覆盖之前，不能跨缺口继承状态；整个计数保持 `null`，不能删去不确定对象后返回偏小的数。
- 数据库、覆盖或必要粗路由筛选不可读时返回 503。没有正式检测语义和处理覆盖的历史源也返回 503，不把旧空结束时间套用为当前检测状态。

前端保留 `null`，并按覆盖端点为短于采样间隔的缺口补断线标记。已知结束时间的边界不包含在活动区间中；实际处理截止也不能当作事件恢复时间。部署前的旧接口仍可能跨截止延伸或漏掉跨月事件，不能与本合同的数值混用。

## 开始、结束、持续和峰值

开始、检测和结束各自对应不同证据。只有生命周期信息适用时，才给出确定持续时间；精确时长、下界和未知分别保留。历史泄漏不能由当前记录确定结束、持续中或恢复。

完成文件模式下，Core 列表与详情的 `item.lifecycle` 使用同一转换：

- `as_outage`／`prefix_outage` 的有效结束时间为 `ended`；显式 NULL 且事件开始到实际处理截止之间连续覆盖时为 `ongoing`。缺字段、空文本或处理缺口保持 `unknown`，不把“尚未结束”延续到墙钟当前时间。
- `data_end_exclusive` 是同一交付版本实际完成文件的排他截止，不是运行计划窗口的终点，也不是入库时间。
- 国家事件读取现有 `country-outage-incident/v2`，按其 `duration_state` 与恢复记录表达检测事件是否关闭；`observed_at` 使用该 incident 的实际最后观察时间。`ongoing` 与 `recovery_state=unknown` 可以同时成立：检测事件没有关闭，不代表已具备全国网络恢复程度的证据。
- 原 `end_time.state` 继续表达字段是否记录，原 `record` 及 `content_version` 保留；新语义以响应的交付 `version` 和 `metadata.interpretation_version=completed-file-results/v2` 绑定。旧按日留存源不添加这组语义。

对于已提供 `item.country_incident` 的国家事件，`peak_at`、`peak_snapshot_id`、`cohort_id`、`asn_membership` 与 `item.asns` 来自同一峰值快照。这里的 AS 名单是峰值成员，不是全事件累计成员或查询时刻成员；数量、分母、比例或快照冲突时接口返回不可用。没有结构化 incident 的旧记录不推定这层口径。峰值时间精度保留在 `milestones.peak.time_precision`，不从摘要文字解析。

AS 中断保存的最大中断前缀数、最大总前缀数和最大比例，可能分别在不同时间更新。不能用“最大中断数÷最大总数”重建最大比例。

峰值反弹、曲线回到窗口起点或数据处理完成，都不单独证明网络恢复。具体事件操作见[查询与解释事件](../guides/event-analysis.md)。

### 完成文件接入后的列表范围

显式完成文件交付模式中，Core 首页读取全部已交付、可解释的六类事件当前记录。兼容事件列表 `/api/v1/events` 继续保留既有筛选：持续时间至少 3 分钟或尚未记录、引用中的事件编号小于 10；默认国内范围，传 `country=all` 才查询全部地域。因此该列表数量不等于 Core 全部记录数，不能把差额称作结果丢失。新结果库没有通过补空结束时间或改编号绕开这些筛选。当前是兼容限制，尚未统一两个入口的筛选合同。

部分文件交付只能说明返回元数据中的实际时段；日历日期出现在目录中不表示整天已完成。实际时段在 `metadata.result_delivery.intervals` 中逐段列出，中间缺口保持未知。

例如只交付 08:00—11:35，小时趋势对应 08:00—09:00、09:00—10:00、10:00—11:00 和 11:00—11:35，不能把最后一个片段称为完整一小时，也不能补出其他二十个小时的零。已覆盖片段没有某类开始记录时，该类可以为零；有不能解释的事件投影时，六类趋势返回不可用。

同一前缀在同一小时发生两次中断，事件开始数是 2，唯一前缀数是 1。它们都不能回答该小时同时中断了多少前缀；后者还需要可靠的结束时间和连续状态。
