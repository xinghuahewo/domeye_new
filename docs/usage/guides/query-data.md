# 选择数据与完成查询

先明确问题要用的结果家族，再确认该家族实际可读的日期、对象和窗口。文档说明“能怎样查询”，当前数据范围由业务接口返回；一个入口有数据不意味着另一个入口也有。

## 第一步：确定问题的对象与数量

写清国家／ASN／前缀／事件、日期或窗口、指标及单位。例如“某 ASN 在一个快照的唯一前缀数”和“该 ASN 的 Feature /24 覆盖块数”是两个问题。选择见[指标目录](../metrics/README.md)。

如果用户只说“前缀数”“事件数”“下降量”，且不同定义会改变答案，先明确含义；如果当前页面和字段已明确语境，可沿用该语境并在答案中给出正确名称。

## 第二步：发现对应数据

| 查询目标 | 如何确认可用范围 | 缺少结果时 |
| --- | --- | --- |
| Core 某日异常 | 请求 `/api/v1/core-overview`；读取所选日期状态及有效返回中的 `metadata.available_dates`、`diagnostic_dates` | 未留存与校验失败分别说明；日期外包范围不代表中间每天可用 |
| 共享 RIB 快照 | `/api/v1/rib-snapshots?date={业务日期}`，或显式要求最近快照时使用 `latest=true` | 未配置不等于零前缀；用户指定日期时不暗换最近日期 |
| 独立 RIB 总体资源点 | `/api/v1/resources` 指定不超过一天的起止时间，检查每个点的时点、主值和单位 | 无点为未计算；单点之间不插值，也不暗取窗口外的最近点 |
| 国家／ASN 活动与资源 | 使用指定对象和时间的 Feature／档案接口，并检查返回时点、样本和状态 | 当前没有统一的全系统可用日期目录；缺少覆盖信息时限定为返回样本 |
| 国家中断详情与同期统计 | 按事件引用调用 `/api/v2/events/resolve`；完成文件响应给出事件、版本和覆盖，再读取同版国家 Feature 与中断时序 | 事件事实和各类统计分别判断可用性；缺失样本保留为空值 |
| 按发布绑定的国家事件观测 | 使用解析响应的发布身份、窗口及 `capabilities` 选择曲线、分类、关联与趋势 | 只读取该发布实际提供的能力，不补造名单或关联 |

以上花括号表示待替换参数。实际日期和事件从查询或当前用户上下文取得，不把本页当作现成数据清单。

## 第三步：保持同一次读取的一致性

共享快照总体和 ASN 查询使用发现返回的同一快照标识。Core 列表和详情使用列表返回的同一引用与版本。完成文件来源的国家详情、同期统计和两窗比较携带同一交付 `version`；按发布读取的国家观测、名单和关联携带解析结果的 `publication_id`。两种身份各自使用，不能互相替代。

这些绑定主要由程序维护，不必在每次业务回答中展示。若绑定已经不可读，应说明变化并重新确认读取范围，不能静默混用不同结果。

## 第四步：读完问题所需范围

Core 使用 `page/page_count`，历史事件使用 `page_num/total_page`。国家 ASN 名单、路径关联和快照审计也各有分页参数，具体见[API 导航](../api/read-api.md)。Feature 国家／ASN 列表的分页按对象，不是把每页当成一个时间片。

只需服务端已计算的总数时，使用其明确统计范围的总数字段；需要全量排名、去重或成员集合时，确认已获取完整对象范围。不能拿第一页最大值称为全局最大值。

完成条件：问题涉及的对象与窗口已确定，实际结果状态可解释，必要分页或服务端聚合范围已确认，指标单位和适用说明一致。详细状态见[结果状态与完整性](../rules/result-states.md)。

## 回答怎样呈现

业务回答默认给出对象、时段／时点、指标名称、单位和结果。必要时加“在该观测范围内”“在已知样本中”“至少”等限定。来源标识、计算版本、算法实现和参考映射保留在内部，不用堆在业务结论后面。

显示示例：“在指定快照中，AS {asn} 有 {N} 条明确起源关联的唯一 IPv4 前缀。”这是表述模板，不是真实结果。若查询未配置，应直接说明该快照数据当前不可读取。
