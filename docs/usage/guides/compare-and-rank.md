# 比较、汇总与排名

从业务问题选择明确指标和总体，再完成所需范围的读取。相同字段名、同一时间窗口或同一页面，不足以保证数据可比较。

## 这段时间撤回占多少

1. 选择普通 Feature 的国家、ASN 或采集范围，确认窗口与活动覆盖。
2. 分别累加适用的宣告 A、撤回 W；相邻请求若包含相同端点记录，先排除重复。
3. 当 A、W 已知且 A+W>0 时，计算 `100×W/(A+W)`；否则说明比例不可计算。

完成条件：分子分母来自同一完整问题范围，未混入不同总体或重复窗口。不要平均逐点百分比。当前档案的兼容零值见[活动说明](../metrics/activity.md)。

## 哪些 ASN 的 IPv4 资源下降最多

1. 先确定比较唯一 CIDR 数还是 /24 覆盖块数，并确定两个时点。
2. 若使用档案，读取单族带符号变化；若使用共享快照，保证两端定义和观察范围可比，再比较对应 ASN 的唯一前缀数。
3. 明确候选范围并确认每个候选所需两端值可用，再按下降量排序。

当前 ASN 档案的默认排行是运营候选集合：由静态优先 ASN、重要 ASN 和窗口异常 ASN 等构成，并可加入指定 ASN。`scope_kind`、`scope_note`、`candidate_pool_size`、`scope_size` 等解释该范围；不是全体 ASN 排名。旧特征列表的默认 ASN 候选也不能视为全部 ASN。

`resource_change` 混合两族不同单位且取绝对值，不用于直接回答“IPv4 下降最多”。接口只返回 Top N、缺少候选完整序列或两端不全时，应将结论限制在现有候选，不宣称全量排名。

完成条件：候选总体、单一指标、两个实际时点、下降方向和并列规则明确。当前接口未提供所需全量候选时，记录能力不足，不转而扫描未授权底层库。

## 昨天发生了多少次前缀中断

先区分三种问法：开始的事件记录数、开始中断的唯一前缀数、某时点仍中断的前缀数。

Core 按日筛选 `kind=prefix_outage` 后，`events.total` 与 `events.distinct_prefixes` 分别对应前两种数量。每小时趋势为每小时开始的唯一前缀数，不能直接累加为全日唯一前缀。生命周期不足的历史曲线不用于确定第三种问题。

完成条件：所选业务日可用，统计对象与筛选范围对应问题，未把修订、每小时重复对象或并发采样混入事件次数。定义见[事件数量](../metrics/events.md)。

## 新增地址能否抵消消失的地址

固定与新前缀可能覆盖同一地址空间。需要具体地址集合，在可比窗口中求并集、交集和差集；两个地址总量相加或相减不足以证明地址空间被补回。

只有汇总曲线而没有可消费成员集合时，可以分别描述固定可见量与新增量的变化，不能给出已经抵消的确定结论。也不能从地址空间变化推断真实用户影响。

## 为什么两个入口回答不一样

依次核对：结果家族、单位、对象总体、观测范围、起止端点、缺失处理、去重方式和并列极值规则。再看数据是否属于同一次读取的内部绑定。

例如国家档案当前包含结束时刻，而 ASN 档案的 Feature 查询排除结束时刻；“资源数量”也可能分别是 CIDR 数和覆盖块数。这些差异没有统一前，应分别解释；完整规则见[时间、汇总与比较](../rules/time-and-aggregation.md)。
