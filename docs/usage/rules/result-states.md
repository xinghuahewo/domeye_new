# 结果状态与完整性

零、空结果、未知、未配置和读取失败表示不同事实。HTTP 请求成功、分页结束或结果处理完成，都不能单独证明源数据完整或网络已经恢复。

## 业务结果怎样解释

| 情况 | 可以表达什么 | 后续处理 |
| --- | --- | --- |
| 确实观测为零 | 对应范围内该指标为零 | 按数值零使用；仍保留对象、时间和单位 |
| 查询完成且没有匹配对象 | 当前查询条件没有找到匹配结果 | 先确认来源可用、查询覆盖和筛选；不要推广为没有发生任何异常 |
| 未知／缺数据 | 当前证据不足以确定数值 | 保留未知；不填零、不自行沿用旧值 |
| 不适用 | 当前对象或样本不满足该指标定义 | 不参与需要该值的计算 |
| 已知下界 | 至少能确定这些数量 | 下界不是精确总数，不能代替精确比例分母 |
| 未配置 | 该入口没有绑定可读结果 | 说明当前能力不可读取；不表示数值为零 |
| 校验或读取失败 | 本次无法可靠读取结果 | 报告不可用；不将失败转换为空列表成功 |
| 部分结果／展示截断 | 仅取得或展示了部分对象 | 说明范围；完成剩余分页后再作全量结论 |

以上是解释规则，不是新增的一套统一 API 枚举。当前接口的状态字段并不相同，调用方需要按实际响应解释。

## 常见接口状态

| 结果家族 | 已有字段或状态 | 使用方式 |
| --- | --- | --- |
| Core | `state=available/window_not_retained/unavailable`；规模、路径等子结果另有 `date_not_retained`、`validation_failed` 等状态 | 分别检查主结果和所需子结果；失败日数值保持未知 |
| 共享快照 | `not_configured` 或服务返回的不可用状态 | 接口存在不表示已登记快照；与异常列表的状态分别判断 |
| 独立 RIB 资源点 | `available/not_calculated/not_configured`；读取失败 HTTP 503；逐指标 `qualified/unknown/not_applicable` | 没有点不等于资源为零；只使用适用主值，不用原始值补缺失 |
| 国家事件 | `observation_state`、`processing_status` 或 `quality_state`，并有 `data_through` | 按响应家族判断哪些观测已可用；不能把 `complete` 当作恢复 |
| 兼容事件接口 | `status:false`、`msg`，有些旧错误响应仍可能使用 HTTP 200 | 同时检查响应正文和 HTTP 状态 |
| 国家／ASN 档案与 Feature 查询 | 参数错误使用 HTTP 400；档案数值 null 与样本数一起返回 | 零分母比例、无样本活动、无前窗环比分别保持不可计算，不补零 |
| 新资格化计算读取 | 可消费主值、raw 记录、未知原因、下界分别保留 | 用适用主值作答；raw 有值不代表它可用于业务结论 |

不是每个接口都提供精细覆盖信息。缺少覆盖证据时，结论应限定于返回数据，不能自行宣称完整。

Core 完成文件模式使用 `result_delivery.intervals` 表示实际活动覆盖；首末时间只是外包范围。六类事件趋势若有不能解释的记录，整体标记 `unavailable`。独立 RIB 的 `observed_at` 只声明时点，不增加该点附近的活动覆盖，也不证明其他时点的资源状态。

## 三个完成状态分别看

**分页完成**表示当前查询的结果页已读完。现有入口分别使用 `page/page_count`、`page_num/total_page` 等字段；未来即使出现 `next_cursor`，游标为空也只说明分页结束。

**源数据完整**表示问题所需的输入和时间范围具有足够证据。分页完成不自动带来这一结论，返回行数或 `sample_count` 也不能独立证明它。

**展示完整**表示回答或页面展示了全部需要呈现的内容。接口全量已取回但只显示 Top 10 时，应说明是前十名，而不是只有十个对象。

## 生命周期与新鲜度

结束时间是否记录与事件是否持续是不同问题。`end_time.state=unknown` 不能否定同版响应中适用的 `lifecycle.state=ongoing`；生命周期的判定依据、适用时间和当前检测器空结束时间的语义见[事件生命周期](../metrics/events.md#开始结束持续和峰值)。

生命周期本身为 `unknown`，或缺少适用的生命周期证据时，不能确认事件仍在持续，也不能确认已经结束或恢复。`is_final`、`is_final_in_data_range`、`data_through` 和处理完成分别描述结果状态或数据范围，不能代替生命周期证据。

资源缺行能否沿用上一条值、活动缺行能否解释为零，必须由该结果家族的稀疏与连续性规则支持。规则见[资源数量](../metrics/resources.md)与[路由活动](../metrics/activity.md)。
