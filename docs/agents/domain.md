# 领域文档配置

本项目采用单一领域上下文，复用根目录 [CONTEXT.md](../../CONTEXT.md)。
前端与后端目录不自动构成不同领域上下文。

## 阅读顺序

1. 探索代码前，阅读 CONTEXT.md，了解产品边界、术语和能力范围。
2. 涉及系统结构与调用关系时，阅读 [系统结构与数据流](../architecture/系统结构与数据流.md)，再核对相关代码与测试。
3. 涉及架构选择时，阅读 `docs/adr/` 中与任务相关的已有决策。

尚无 ADR 时正常继续，不为满足目录结构而创建空目录、模板或假设决策。

## 内容归属

各类知识的权威位置以 [README 的文档路由](../../README.md#文档导航与权威位置) 为准。
本文件只维护工程技能的领域文档阅读规则，不复制产品事实、术语定义或架构结论。

已确定架构决策及其理由进入 `docs/adr/`；
只有存在明确决策依据和实质内容时才创建相应记录。

## 术语与冲突

- Issue、方案、测试和代码讨论使用 CONTEXT.md 中定义的领域术语。
- 缺少必要术语时，指出具体缺口，再按任务范围补充；不自行假定已有定义。
- 方案与已有 ADR 冲突时，明确引用对应 ADR，并说明建议重新讨论的理由。
- 未批准的方案不能覆盖当前架构事实；无法确认的判断标为 Unknown。
