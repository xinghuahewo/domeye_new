# 问数服务

问数应用位于 [apps/query](../../apps/query/README.md)，使用独立 Node 进程和 systemd 服务，读取服务器现有只读 API。主前后端、独立 A 服务和数据计算任务分别运行，不随问数服务发布而切换。问数只纳入本项目结果，不纳入旧项目 55 天数据。

## 服务器布局

| 项目 | 位置 |
| --- | --- |
| 内网入口 | `http://10.99.8.16:28684/` |
| 服务 | `domeye-query.service` |
| 发布入口 | `/home/bgpdata/domeye-new-releases/query-current/apps/query`，符号链接指向具体发布目录 |
| Node 24.12.0 | `/home/bgpdata/domeye-new-runtime/query/toolchain/node/bin/node` |
| 配置 | `/home/bgpdata/domeye-new-runtime/query/config/service.env`、`model-config.json`，均为 0600 |
| 状态 | `/home/bgpdata/domeye-new-runtime/query/state`，由专用 `domeye-query` 用户读写 |
| 历史 | 状态目录的 `history/`；原本地历史迁入时逐文件校验，原件保留 |
| 文档来源 | Git 标签 `query-docs-20260923`，固定提交见应用说明 |

服务环境变量示例（没有密钥）：

```ini
PATH=/home/bgpdata/domeye-new-runtime/query/toolchain/node/bin:/usr/bin:/bin
HOME=/home/bgpdata/domeye-new-runtime/query/state
DOMEYE_MODEL_CONFIG=/home/bgpdata/domeye-new-runtime/query/config/model-config.json
DOMEYE_QUERY_STATE_DIR=/home/bgpdata/domeye-new-runtime/query/state
DOMEYE_CHAT_HOST=10.99.8.16
DOMEYE_CHAT_PORT=28684
DOMEYE_CHAT_ORIGIN=http://10.99.8.16:28684
```

沿用主项目内网访问边界，无公网入口和多用户账号。浏览器来源严格限制为配置的 origin，不根据请求自动放宽，不信任转发头。若以后另行配置代理，须原样传递合法 Host／Origin、关闭流式响应缓冲，并容许长回答；不把反向代理默认短超时变成问数限制。

## 发布顺序

1. 从服务器已提交的 main 创建独立集成分支，只合入本模块与运行说明；保留共享源码目录的其他未提交改动。程序检查和 Linux 验证通过后，服务器 main 快进到集成提交。
2. 从该提交导出发布目录，保存 `source-commit.txt` 和源码摘要；使用锁文件在 Linux 安装应用、QMD 依赖。专用用户不能改写发布代码和模型配置。
3. 按应用说明准备固定文档和索引，核对 20 篇原文、向量完成状态与模型摘要；迁入已有会话并核对摘要。该准备只构建检索索引，不运行业务计算。
4. 核对两套既有 API 的健康与实际合同；在待发布应用上完成真实问题与停止、历史检查。切换 `query-current` 后安装[服务模板](../../deploy/systemd/domeye-query.service)，执行 `systemctl daemon-reload` 和 `systemctl enable --now domeye-query.service`。
5. 复核 HTTP、真实问答、浏览器呈现、`systemctl show` 的运行目录与 `/proc/<PID>/cwd`、发布源码摘要、服务启用与重启次数。HTTP 200 只说明入口可达，不代表数据或答案验收。

配置文件通过宿主部署渠道传送，不写入仓库、命令行或日志。问数运行中不下载安装依赖，不升级 QMD，不下载模型，不恢复或计算业务结果。

宿主私有目录 `/home/bgpdata/domeye-new-runtime` 保持原所有者与其他用户权限，通过 `setfacl -m u:domeye-query:--x /home/bgpdata/domeye-new-runtime` 仅允许专用用户穿过到问数子目录，不允许列举目录。配置目录为 root:domeye-query、0750；模型配置为 domeye-query 所有、0600，环境文件由 root 持有、0600。发布源码与 Node 由 root 持有并只读使用；systemd 将文件系统设为只读，仅放行问数状态目录。不要为解决目录访问而放宽整个私有运行目录。

## 查看与回退

```bash
systemctl status domeye-query.service
systemctl show domeye-query.service -p MainPID -p WorkingDirectory -p ExecStart -p NRestarts
journalctl -u domeye-query.service -n 50 --no-pager
curl --fail http://10.99.8.16:28684/api/healthz
```

后续升级先保留原 `query-current` 目标。需要回退应用时，停止问数服务，将该链接原子切回上一发布目录，再启动并检查；保留状态目录、历史、业务数据库及其他服务。首次部署没有上一服务器问数版本，回退为停用 `domeye-query.service`，原本地应用和记录仍保留。回退按具体故障或用户授权执行，不为演练影响正在进行的问答。
