| 边界 | 实际限制与失败行为 |
| --- | --- |
| 窗口／候选 | 最多31个完整业务日、64条路径声明（包含别名）；清单与登记索引各不超过1MiB，超限中止 |

### 隔离观察流水线的 DuckDB 线程预算

观察流水线共享连接构造器 `backend/data_pipeline/bgp/archive/store.py:connect_duckdb` 使用 `DOMEYE_DUCKDB_THREADS`，未设置时默认2。配置只接受不带符号、空白或前导零的十进制正整数；空值、零和非法值在创建原生连接前拒绝。预算直接传入 `duckdb.connect`，在扩展 LOAD 前生效，覆盖生产、封存及共享只读连接；调用者原有内存预算继续生效。每个连接的实际值可用 `SELECT current_setting('threads')` 核对，taskset 或 OMP 配置不能替代此检查。

该值限制每个 DuckDB 连接的线程预算，不是整个进程或所有原生库的总线程上限，也不替代 RSS、磁盘和 PG 资源保护。调整预算不增加整体处理截止时间；真实批次容量仍须单独验证。共享构造器源码变更会进入观察 `code_identity` 并改变 plan 身份，旧 CP 不得隐式按新代码恢复；保留原 run 与原件，使用新 plan/run 重新生产，已封存版本的再准入遵守既有校验。

### 首份 RIB 原生 M2 候选

`scripts/native/observations-native-rib.py --config <Git外配置.json>` 是显式实验入口；默认观察生产入口不切换。只接受一份 RRC25 TABLE_DUMP_V2 普通 IPv4／IPv6 单播 RIB，不接受参考文件、UPDATE 或其他 MRT 类别。只完成观察 checkpoint 和 seal，不执行 M3 或业务发布。真实文件性能结论必须绑定本次代码、构建、输入和运行回执，不能用解析器单独完成的时间代替 M2 总时间。

迁移方向与解析权威见[统一解析通路决策](../adr/0002-layered-data-storage.md#统一解析通路2026-09-15-已接受待完成迁移)。本次候选仍使用少量旧解析器样本做独立证据核对，不把旧解析器当作文本格式权威。

构建使用本项目锁定 Python 环境中的 Arrow 23.0.1 头文件和库，以及固定 RIPE NCC bgpdump 提交 `63fe1c50c7d07bb4c57d4fcc690696adc9b3c306`。在 Linux 的 Git 外目录运行 `scripts/native/build-observation-native.py`，显式传入已核对 SHA 的上游归档、构建输出目录、bzip2 与 SQLite 开发文件的解包前缀；不做系统级依赖替换。构建回执记录原生源码及二进制 SHA。适配器只为固定头／正文增加捕获点，并修正上游 gzip EOF 分支错误使用历史 `errno` 的问题；实际压缩错误仍拒绝，独立完整 gzip 扫描另外校验 EOF／CRC。

流水线先核对原件及全部消息边界／摘要，再由 C 库解码，通过 SQLite 唯一键索引及有界缓存复用路径。Peer 地址和 AS 路径文本以固定 libbgpdump 为准，不额外转成旧 Python 的字符串表现；前缀以解码地址生成规范网络键，原始 NLRI 字节另列保存。原始属性及 AS_SET／AS4_PATH 字节保留，项目归属规则与解码文本分开。Arrow 背压目标为 4 个未消费段；生产当前段时最多额外保留 1 段，每段构造缓冲以 64 MiB 为触发阈值，单个完整 MRT 记录不拆开。集中写入 Parquet 后读回并进行列式内容对照，同时计算实际落盘行的摘要，再在同一 DuckLake 事务中登记文件和分段回执。登记使用 [ducklake_add_data_files](https://ducklake.select/docs/stable/duckdb/metadata/adding_files)，文件所有权转交 DuckLake，禁止另外覆写或清理这些文件。

原生候选的暂存 Arrow 使用 LZ4 IPC 压缩，C 进程的 Arrow 压缩池上限为 4 线程。SQLite 页缓存预算为 256 MiB，原始属性缓存仍为 32 MiB；连续三段共用一次 `synchronous=FULL` 提交，各段 Arrow 与目录先同步、字典事务成功后才公布分段回执。不足三段的文件尾部同样先提交再公布。背压计数包含尚未公布的段；达到阈值后先等待消费再继续解码，DuckLake 仍按段登记。恢复只承认连续且已核验的回执，清除其后字典记录与未完成输出，再重做对应段；一组回执只公布一部分不等于整组完成。这些设置属于独立原生候选，完整文件性能结论以对应运行回执为准。

`native/binding.json`、连续且已校验的 `segment-*/committed.json`、路径索引和 DuckLake 分段回执共同支持恢复。未完成段重做，已登记段先核对身份与文件摘要，不能重复登记。解析尚未完成时，恢复仍需从 gzip 开头读取，当前 C 库还会再次解码已提交前缀，只复用其列式输出、去重与落盘；它不是压缩流随机定位恢复。只有完整 EOF、全部核对、文件 checkpoint 和最终 seal 成功，才有观察封存资格。

并行消费只接受已经包含 `files` 摘要的完整分段回执；在本轮目录扫描后才出现的新回执等待下轮核验，不能先登记再补摘要。早期候选触发过该竞态：仅在逐项验证已登记 Parquet 的原 SHA、行数及 Arrow 逻辑内容后补齐候选回执；被清理的尾段暂存 Arrow 可从对应已验证 Parquet 重建，原始 MRT 和 Observation Parquet 不改写。修复清单和代码／plan 变更记录保存在 Git 外，不自动套用于其他历史运行。

原生 typed 摘要沿用 `checkpoint.sha` 的 v1 编码，摘要输入是新解码器的实际输出，不要求与旧解析器的文本摘要相同。分段读回后计算行摘要，最终只排序位置键和 32 字节摘要，保持原排序、重复记录、原始字节及 null 的含义。临时行摘要不跨进程复用；恢复时重新从已核对 SHA 的 Parquet 计算。最终核对固定快照行数、消息／元素连续性、引用关系，以及快照文件与分段读回时的 SHA 绑定。全部消息定位／摘要、全部原始前缀和分层证据样本分别核对；文本通过同版本上游 CLI 回归，固定样本不能证明尚未支持的 MRT 类别。`native-eof.json` 只代表原生阶段完成，不能作为 M2 完成标志；最终以 `execution.json`、PG seal 和固定 DuckLake 选择共同核对。

完整源到列核对回执和原生 EOF 已齐全、仅 checkpoint／seal 未完成时，恢复直接核对输入与构建、连续分段登记及每个 Parquet 的原 SHA、行数，再从实际文件重新计算行摘要；不再读取用于解析传递的暂存 Arrow。此路径仍保留全部固定快照校验。原生候选的元素序号判据按 `hash(message_id) % 16` 分区执行，同一消息的全部元素在同一区，完整保留最小值、最大值、总数与 DISTINCT 数的原判据；降低单次聚合驻留规模，避免一次聚合 5,571 万元素时的内部内存失败。分区并非减少校验行数，适用容量仍须实测。

运行配置需显式给出私有 PG、构建目录、输出目录与 cgroup 采样根。真实试验使用独立 systemd 服务和私有 PostgreSQL，共用 8 核／16 GiB 父 cgroup；服务需指定运行用户，确保 DuckDB 能找到该用户的扩展目录。原件绑定为只读，使用 `KillMode=control-group`，截止或强制中断时连同解析子进程一起停止。默认试验硬截止为 30 分钟；每两个连续 60 秒窗口按已持久化元素估算余量，预测总耗时超限则提前失败并保留现场。用户明确改为先跑完时，可显式设置 `deadline_seconds: null` 并移除该服务的时间截止，资源和完整性保护继续有效。最终校验预留值是预算，不是已测量耗时；完成优先运行不能宣称通过 30 分钟性能门槛。

时间策略修改也会进入代码身份，不能直接冒用旧 plan。对尚未选出任何 checkpoint 的本次私有候选，续跑已将仅涉及时间保护的精确源码差异、旧／新 plan 及用户变更原因保存在 Git 外回执；原件、原生构建及全部数据处理代码保持绑定。其他代码变化不由此获得复用资格。CPU、RSS、I/O 与阶段耗时写入资源及运行回执；整机 CPU 能量计数只能作为共享主机的参考读数，不能当作本任务或单个环节的专属电耗。

原生计时另外记录字典初始化／回退、Arrow 写入、SQLite 提交、自动 WAL checkpoint、最终 WAL checkpoint 及关闭。`write_seconds` 包含 Arrow、提交、回执同步与末尾清理；自动 checkpoint 在触发它的 SQL 内执行，不能再与这些上层耗时相加。自动 checkpoint 采用 131,072 页门槛与 PASSIVE 模式（新建索引默认 4 KiB 页时约 512 MiB）；门槛在 FULL 提交之后判断，日志峰值还包含触发它的当前事务。该设置只降低主库合并频率，不降低提交持久性；[SQLite WAL hook](https://sqlite.org/c3ref/wal_hook.html) 在事务提交之后计时，结束前严格执行最终 checkpoint 并关闭索引，成功后才生成原生 EOF 回执。冷／暖缓存短实验分别报告，复制种子与预读时间单列，不能把冷启动随机 I/O 或组件吞吐直接当作完整 M2 预计时间。

最终路径唯一目录的独立计数前，使用 4 MiB 缓冲顺序预读 SQLite 主文件，随后仍执行原来的只读 `SELECT count(*)` 并与实际落盘路径数比较。它只改变读取方式，不用生产端计数替代独立校验；`path_index_prefetch` 与 `path_index_count` 分别计时，均属于上层 checkpoint 的子项。该措施针对实际首 RIB 冷态 B-tree 遍历的随机 I/O 等待，不能把预读耗时移出完整运行的时间预算。

Linux 上每段完成 Parquet 读回、摘要计算与目录提交后，对已经读完的临时 Arrow 文件使用 `POSIX_FADV_DONTNEED` 建议释放页缓存，给仍需随机访问的路径字典留出空间。文件、分段回执及最终 SHA 校验全部保留；最终再次核验临时分段后也释放其缓存。不支持该接口的平台跳过建议。`ipc_cache_release` 与 `native_output_verify` 分别记录缓存处理和最终临时输出核验时间；缓存释放是操作系统建议，不保证每次释放相同数量的内存。

### 多文件原生 M2 候选

`scripts/observations.py checkpoint` 的 Git 外配置可显式指定 `native_build`，接入 `native-mrt-columns/bgpdump-v3`。未指定时保留原入口。配置仍使用 `dsn`、`catalog_data_path`、`read_policy` 和 `limits`；批大小不得超过 200,000。指定 `resource_cgroup` 时按秒保存父组的 CPU、内存、进程和 I/O，以及可读取的整机 CPU package RAPL 原计数。原生多文件入口不设总时间截止，继续执行内存、磁盘、来源身份和持久化检查。

该候选沿用现有八张观察表、M2 checkpoint／seal、参考资料导入及跨文件上下文。RIB 走原生列式入口，BGP4MP／BGP4MP_ET 支持 A/W、MP NLRI、EOR、Add-Path、AS2／AS4、LOCAL、状态变化以及库已支持的非路由消息；库未实现的 ROUTE_REFRESH 明确标为 unsupported。LOCAL 的原 Peer 是库解码结构的 destination，不能误用库为发送方向规范化后的 source。拒绝帧不输出半条元素或路径；可信头保留在 interpretation，完整原帧的定位与 SHA 保留。`isolate-payload/v1` 可继续读取完整坏帧之后的消息，压缩／帧截断、无效扩展时间头、写入及资源错误仍停止。

每份 MRT 使用稳定 attempt 与独立路径索引，恢复只复用已验证的连续分段和已选出的文件 checkpoint。消息关联与跨文件时间诊断沿用现有规则。跨文件封存读取已绑定实际 Parquet 的路径行摘要，以原生 Arrow 流构建临时 SQLite 所有者索引：相同 key 的不同 typed 正文拒绝，所有者按声明源序选择。临时索引失败后重建，最终所有者和选择关系仍在 DuckLake 事务中持久化并读回核对；不重写全部观察行。

当前验证覆盖原生 RIB／UPDATE、多文件 checkpoint、恢复及真实 UPDATE 的独立试验；真实日 M2 封存、后续计算、独立发布与产品验收需分别报告。解码器替换和契约升级的判断以[统一解析通路决策](../adr/0002-layered-data-storage.md#统一解析通路2026-09-15-已接受待完成迁移)为准，不能把旧解析器所有输出都作为兼容目标。

## 排障与恢复边界

| 现象 | 检查与处置 |
|---|---|
| 端口占用或前端严格端口检查失败 | 核对对应服务和监听进程；避免前台与 systemd 重复启动，不直接终止其他项目服务 |
| 缺少 Python 或前端依赖 | 核对本项目依赖目录；按 README 的安装流程恢复，前端 Node 选择逻辑以启动脚本为准 |
| 后端运行配置被拒绝 | 核对项目外普通文件、权限和允许键；不要直接打印含凭据的完整文件 |
| 服务持续失败并达到启动限制 | 先读取日志并修复原因，再使用 `systemctl reset-failed <对应服务名>` 和 `systemctl start <对应服务名>` |
| 旧 P0 或 dashboard 接口返回 404 | 新源码已退役这些入口；按业务 API 导航迁移，不通过设置旧变量恢复 |
| 国家中断返回不可用或发布不匹配 | 核对请求的发布身份、实际选择的制品及其完整性；来源选择规则见架构文档 |
| 远端可访问、本机打不开 | 核对客户端隧道、本机端口和远端目标；无需因此重启正常的后端 |

恢复现有运行环境时，先核对项目路径、生效 unit、独立运行配置及所引用的数据目录，再恢复本项目依赖，最后启动服务并进行上述检查。路径或配置变更后重新核对服务实际使用的位置。

完整源数据库、原MRT／INFO／P0或原机不可用时的全站恢复仍未验收。C消费副本的本机独立恢复已验收，范围见[台账第49节](../data-assets-and-admission.md#49-当前37e版本的独立恢复与空国家原文复核)；本次另准备服务版本回退，但不等于全源数据或异地灾备恢复。运行重启、消费恢复与源数据修复分别记录。

## 文件级路由状态流水线的隔离运行

候选入口 `scripts/observations.py route-pipeline` 已改为原生有序批次直接消费，仍使用完整文件级 checkpoint。需要本项目 Python 3.10 锁定环境、按当前原生源码构建的 Linux 工具，以及显式绑定的私有 PostgreSQL／DuckLake 数据根。能力与语义边界以[系统结构](../architecture/系统结构与数据流.md#文件级路由状态流水线隔离候选)为准。

2026-09-18 共享内存简化先在本地 `72ae` 交付，后按用户要求[同步源码目录](#2026-09-18-源码目录同步)，没有重启服务或启动数据任务。下列命令不是此前伊朗任务的继续运行指令；该任务已取消并清理，不能从已删除目录恢复。源码版本、业务配置和实测范围的区别见[加速改动汇总](../architecture/数据流水线加速改动与当前困境.md)。新任务须重新绑定独立输出和同版源码，不沿用旧版本的恢复通过结论。

Git 外配置使用 `dsn`、`native_build`、`catalog_data_path`、`read_policy`、`limits`。`limits.batch_rows` 为原生段行数触发值（1–200000）；原生在输出当前段后按 4 段阈值等待，最多保留 5 个已生成而未确认段，计算在途任务最多 1 个。新入口不使用 `max_pending_files`。`audit_transitions` 默认 false；true 时额外保留逐条 canonical 对照数据，不适合作为大规模默认输出。

```bash
uv run --frozen --project backend python scripts/observations.py route-pipeline \
  --config /绝对路径/私有配置.json \
  --manifest /绝对路径/已绑定输入清单.json \
  --output /绝对路径/新候选目录
```

需要 Feature／Detection 时，在私有配置的 `business_config` 指定另一份 Git 外 JSON 的绝对路径。该 JSON 必须显式提供以下内容，不能把缺失参考或未知覆盖填成完整：

| 字段 | 内容 |
| --- | --- |
| `feature_reference` | 现有 Reference 的 `version`、`country_names`、`country_codes`、`big_countries`，可带保留原行的 `source_rows` |
| `detection_reference` | 现有 ReferenceBundle 的版本、原行、证据引用和全部解释映射，历史适用性未证明时保留 Unknown |
| `windows` | 以本清单基线及全部 UPDATE 的 source_id 为键；每项有带时区的 `start`、`end`、`file_time`、`coverage`、`message_quality_state`；UPDATE 另显式绑定旧规则使用的 `legacy_tables`，这些表名只是候选引用，不写旧业务表 |
| `feature_modes` | 默认 `ordinary`、`ir`，可显式选择其中一种 |
| `detection_enabled` | 默认 true；false 时仅运行所选 Feature，不装载检测参考、不维护检测路由、不生成检测事件；无需 `detection_reference` 或窗口中的 `legacy_tables` |
| `audit_detection` | 默认 false，省略可由 Observation 重放的逐条兼容转移、规则跟踪和查询审计；事件修订、业务结果及资格证据仍保留。true 用于完整旧算法输出对照 |

JSON 内容摘要、代码、原生构建、输入清单和规则共同绑定候选。旧 Detection 的集合枚举存在进程差异，因此业务运行还绑定 Python 版本、散列种子和指纹。CLI 未指定 `PYTHONHASHSEED` 时以 0 重新启动；直接调用 Python API 的进程须在启动前显式设置固定种子（推荐 0），运行中修改环境变量不能更换已生效的散列环境。恢复必须匹配原解释器与种子；本次保留旧算法，不把随机集合槽位重新定义为排序后的业务规则。未配置业务输入时只运行基础状态链路，回执显示 `features: not_run` 与 `detection: not_run`；不能据此宣称业务完成。提供业务配置后，所选普通／IR Feature 逐窗口输出；启用 Detection 时保留活动事件并在文件尾执行既有规则。所有结果写入候选 Parquet，不直接发送通知、交付结果或发布版本。

仅伊朗特征使用 `feature_modes: ["ir"]`、`detection_enabled: false`；沿用既有 IR 过滤和计数规则。原始 MRT 仍完整解析、归档并维护规范状态，不截断非伊朗输入。回执必须标明 `detection: not_run`，恢复须匹配检测启用配置。该选项已通过与既有 IR 算法逐窗口及恢复对照；真实单日完成状态另见执行回执。

真实 CSV／Excel 参考可能含整数键或空单元格产生的 NaN 键，业务身份摘要复用既有保留类型编码，不对异类键直接排序，不改变原映射。普通 JSON 对象不能无损往返这类键；此时应由同版 `ReferenceView`／`load_reference` 生成内存映射后调用 `run_pipeline`，不能为了使用 JSON 配置把键统一转为字符串。原件、原始行和解释版本须另行绑定并保留。 配置身份使用同字节合同的分块摘要，不改变已有摘要值；每次规范化设 4096 个值节点预算、外层分组最多 128 项。原参考、最大容器排序键表和单个大字段仍占内存，仍须设置整体 RSS 保护。该实现有省内存、增加 CPU 时间的取舍，不能从摘要阶段推算整体处理速度。

隔离 systemd 服务可能没有用户主目录。启动前显式配置 `DOMEYE_DUCKDB_EXTENSION_DIRECTORY`，指向本轮独立目录中的对应版本 DuckLake／PostgreSQL 扩展，并以服务相同环境验证 `LOAD ducklake` 与 `LOAD postgres`。扩展版本须匹配锁定 DuckDB，记录二进制摘要；不以放开原始数据目录写权限修复初始化错误。

DuckLake catalogue 的数据根绑定在数据库级。同一私有 PG 数据库内另建运行 ID 或 schema，并不能同时改用另一个数据根。需要独立目录的修复试跑应使用独立私有数据库；保留旧候选与绑定，不通过 `OVERRIDE_DATA_PATH` 将旧 catalogue 指向新目录。

恢复时使用相同配置、清单、代码、构建和输出目录再次执行。`pipeline-run.json` 固定身份，`m2/` 保存 Observation 归档，`route-files/` 保存候选结果。PG `route_file.runs` 保存工作态元数据和消费游标，`route_file.packed_rows` 保存紧凑规范态，v2 的 `route_file.business_rows_v2` 保存业务计数、活动事件、必要索引与恢复引用，`route_file.business_manifests_v2` 绑定基线及变化清单链，`route_file.files` 保存连续文件提交及结果摘要；`route_file.rows` 只供详细审计或旧文件入口的兼容状态。只认这些事务记录，`events.jsonl` 不是恢复游标。

计算中、结果文件已写但状态事务尚未提交时，当前内存态作废，恢复上一个完整文件。已核验的当前归档段可复用，必须重新驱动未提交计算；状态提交已成功但确认丢失时，读取并核验提交后继续，不重复累计。恢复逐行验证状态摘要、对象顺序、数量及基线／变化清单摘要链，也核验所有引用结果文件；缺行、多行、损坏或绑定不符均拒绝继续。基线前参考文件不伪造业务状态，独立 RIB 快照不推进业务游标。 恢复验收须注明对照基准：提交前完整候选与另一次从空状态正常完成的结果是两类证据，不能互相冒充。故障取证脚本异常须单独记录；只有实际确认强制终止及外部数据库回滚后，才计作该强杀边界通过。

计算期间不再向 PG 刷新规范路由槽：RIB 文件末从唯一状态表分批保存；UPDATE 文件内只记变化键，完整 EOF 与归档核验后集中写最终值。二进制 COPY、业务变化保存、结果引用和游标仍在同一文件事务提交。失败后丢弃整份未确认内存，从上一已确认文件及核验归档恢复；没有新增每十份文件快照或跨版本迁移。新代码未同步到运行中的前后端，也未重新开启已取消的伊朗任务。分项实测和验证限制见[系统结构](../architecture/系统结构与数据流.md#文件级路由状态流水线隔离候选)。

2026-09-18 本地源码的 `route-batch-pipeline/v3` 已取消计算侧 `hot-paths-*.sqlite`：路径解释保存为紧凑内存记录，路径文本共享，旧路径直接在内存解引用。展开行缓存仍限 8192 项／8 MiB、批次准备设 64 MiB 保护；编号索引和去重文本随路径数增长，必须计入整体 RSS，不能当作固定缓存。历史 SQLite 缓存不参与新版本恢复；完整 Observation 及已引用结果不得随缓存删除。端点和 Peer 证据另有数量保护。时点转换和短字段排序键各有 4096 项缓存，只读 AS 关系按单次业务运行缓存最多 8192 项；均不参与恢复身份或跨进程复用。窗口／活动事件的高基数工作态仍依赖整体 RSS 保护，未实现磁盘自动淘汰，也没有证明 64 GiB 足够处理真实 RIB。

默认 UPDATE 的计算批最多包含 1024 个元素和 1024 条新消息，独立于原生 Arrow 段的行数阈值。批次可以截在一条消息内部，但控制消息、元素原序和本条状态／业务调用必须交替保留；不是先把整批状态更新完再运行检测。归档已确认而计算失败时，恢复仍重放本文件的已核验段，不能跳过已归档的 UPDATE。`audit_transitions` 保留原逐元素路线，用于离线审计和有界真实对照；两种模式不能据此跨源码身份混用恢复游标。

共享前缀解释缓存最多 4096 项，仅保留长度不超过 128 字符的原始键及不可变网络属性，重启后重建；严格解析与 Feature 的过滤单位不变。业务结果的合并编码在同步回调返回前冻结正文，文件末仍须读回核验和提交状态事务。紧邻路径快照只复制当前前缀的编号槽；本轮增量保存升级为 `business-state/v2`，旧候选不原地迁移；必须使用同一源码绑定恢复，不能将旧版本的强杀恢复成绩当作新版本已重跑。

`native_rib_state` 默认 false；true 仅供原生紧凑状态编码对照，并进入运行身份。首次真实 RIB 片段中其编码未快于 Python，因此没有自动切换默认值。它不改变 libbgpdump 解码器；路径、端点和业务规则保持一致。

默认 RIB 基线可走列批计算，消息及诊断仍按原边界校验；8192 行是窄列预取上限，路径准备另受 64 MiB 保护。详细审计、受限 RIB 及混入 RIB 消息的 UPDATE 段继续使用原逐元素流；普通 UPDATE 按上一段的列批入口执行。端点索引只引用现有状态键，恢复时由校验通过的紧凑行重建，不另存第二份路由负载；STATE 的失效条件和最后已知状态含义不变。固定字段合同、方向枚举和摘要格式的校验规则在进程内复用，端点地址解析缓存最多 4096 项。实现细节见[文件级路由状态流水线](../architecture/系统结构与数据流.md#文件级路由状态流水线隔离候选)。

`m2/native-file-*/native/segment-*` 的 IPC 与原生磁盘索引仍保留，未启用自动清理。文件确认前，原生恢复与完整校验仍会读取它们；文件确认后，直接计算恢复使用 checkpoint 引用的 Parquet，但不能据此无差别清除其他原生／离线入口需要的文件。本轮磁盘测量包含这些副本，未将它们标为已退役。

`limits.max_rss_bytes` 保护 Python 进程峰值；联合预算还必须涵盖原生子进程、Arrow、DuckDB 和私有 PG，不能只看净状态负载。真实试跑需另行核对输入、独立输出位置、整体资源预算和授权，并保留实际运行回执，不能沿用 fixture 与合成数据的通过结论，也不能恢复已清理任务。新入口不默认设置 30 分钟强杀。磁盘保护继续生效，未知临时文件和未引用候选不自动批量删除。原生进程设 Linux 父进程退出保护；进程退出、持锁会话释放后再恢复。

`endpoint-inventory.json` 保存端点预扫及原生 CPU 时间，`m2/` 保存完整扫描、原生解码、归档和封存阶段记录。`route-metrics-*.json` 保存直接批次、归档重放、状态恢复、状态写入、业务状态写入、结果读回、最终校验、队列峰值和缓存峰值；`single_writer` 单列 RIB／文件控制处理和 UPDATE 整批的线程 CPU／墙钟时间，UPDATE 不逐元素计时。 `business_config_digest` 单列完整配置摘要，`state_business_initialization` 单列工作态构造及恢复；参考加载发生在调用者中时，须另记进程启动到入口的时间并纳入总耗时。阶段可包含子项且归档／计算重叠，CPU 和 I/O 的进程累计值不能简单相加。未采到短阶段 RSS 时为 Unknown。配置 `resource_cgroup` 可另采样整组资源；共享宿主 RAPL 不能分摊成每模块功耗，没有可归属计量时 J／Wh 为 Unknown。

`scripts/benchmarks/benchmark-route-batches.py memory` 在新进程测人工状态 RSS；`--compact` 使用新规范态。`pipeline --output 新目录` 创建／删除专用测试数据库，手工生成 1 RIB＋3 UPDATE 并运行完整归档、计算、状态持久化和封存；`--business` 同时执行既有业务。两者只读取显式 `DOMEYE_M2_TEST_DSN` 和 `DOMEYE_NATIVE_BUILD`，只允许有界人工规模。报告必须注明是否包含业务，不能将基础解析／状态吞吐当作真实全链路速度。

旧整文件入口通过同一命令脚本的 `route-file-pipeline` 调用，保留 `max_pending_files`（默认 2，1–8），用于离线审计和原有恢复对照；不是新实时计算主线。旧 `mrt-interpretation/v1` 与原生 `mrt-interpretation/bgpdump-v1` 保持各自校验，受限消息保留原生诊断和可信头，不伪造旧解析器字段错误。所有 fixture 与合成测量均不能代替真实 RIB、全日运行、跨存储交付、发布或断电恢复验收。

### 完成文件结果交付（隔离流程验证）

实施范围和语义见[迁移计划的 44 份验证](../architecture/新架构一日全链路迁移计划.md#2026-09-22先用-44-份完成文件验证交付流程)。先准备专用空 PostgreSQL 库，写入连接串保存在 Git 外权限 0600 的文件；交付器拒绝在已有业务表的库初始化。仅显式离线命令写库：

```bash
PYTHONPATH=backend backend/.venv/bin/python scripts/pipeline/deliver_results.py \
  --run /path/to/completed-source-run --files 44 --dsn-file /path/to/writer.dsn
```

`--files` 表示从 ordinal 0 起的连续完成文件数量，不是 UPDATE 数。重复运行先校验既有回执，不重复计数；新文件失败后检查具体错误，修正适配或输入绑定后重试，不忽略未知异常。原始运行的失败和归档状态不能改写。

查询使用独立只读账号，把 `DOMEYE_RESULT_DELIVERY=true` 和专用库配置写入项目外 `backend.env`，按既有受控启动器启动隔离后端。不要同时绑定旧首页、RIB 或国家增强制品来拼接本轮数据。`/api/v1/healthz` 的 `result_delivery` 说明实际文件数和时段；所有 GET 的 `X-Domeye-Result-*` 响应头说明请求绑定。存活探针为 ok 不代表结果完整。Core 列表详情继续要求同版引用。

需要独立 RIB 规模时，复用同一原件的已保留完整原生归档，使用本项目解释器显式运行以下两步。准备目录必须是新目录；写入目标仍为已经交付该源完成文件的专用库。

```bash
PYTHONPATH=backend backend/.venv/bin/python scripts/pipeline/rib-statistics.py prepare \
  --source-run /path/to/completed-source-run --archive-run /path/to/retained-archive-run \
  --ordinal 0 --output /path/to/new-statistics-directory
PYTHONPATH=backend backend/.venv/bin/python scripts/pipeline/rib-statistics.py deliver \
  --artifact /path/to/new-statistics-directory/statistics.json --dsn-file /path/to/writer.dsn
```

准备命令核对原件摘要、原源完成计数、连续段登记和正文；早期路径登记没有逐文件行数时，从 Parquet 页脚读取并与原段总计数闭合。默认 DuckDB 4 GB／4 线程、Python RSS 8 GiB、临时空间 40 GiB、磁盘至少空闲 50 GiB；运行器仍须设置进程组限额。只对同一原件摘要、无解析缺口的 RIB 生成统计。未知起源保留未归属计数，不解释成源损坏或自动补单 ASN。

交付为一个独立事务：相同统计重复提交返回 `already_delivered`；同源不同统计拒绝覆盖。将新表 `result_delivery.rib_statistics` 的 SELECT 权限授予现有查询账号，不授予写权限。新统计身份会改变整体查询版本，前端重新读取后再使用同版事件引用。`/resources` 缺表或无该时点时不补算，读取错误也不返回零。历史归档与计算的暂停状态不受这两个命令影响。实际资源和验证证据统一记录在[44 份接入验证](../data-assets-and-admission.md#44-份完成文件的系统接入验证2026-09-22)。
