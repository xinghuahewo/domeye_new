## 已知差异与未决事项

| 问题 | 本次文档如何处理 | 后续何时可以改变结论 |
| --- | --- | --- |
| 同名“前缀数”对应 CIDR 数、/24 块数或 /48 块数 | 已按结果家族明确单位及例子 | 只有正式改变该家族定义并处理历史兼容后才能合并 |
| Feature 覆盖折算与国家精确地址并集不同 | 分开定义、禁止直接对账为同一指标 | 需明确提供可比的同一成员集合与量纲 |
| 历史方向按独立 peer ASN，新方向按 endpoint×prefix | 分开解释；别名映射不作为等价证据 | 需核对具体发布算法、总体和分母 |
| 历史受影响／路由中断 ASN 分类的互斥与纳入算法 | 保留 Unknown；不套用新计算的互斥分类 | 需找到对应历史生产实现及结果证据 |
| 旧 IPv6 地址等价量的精确精度与舍入 | 使用旧结果定义，不自行套用新分数量纲精度 | 需核对该历史结果的生产与序列化行为 |
| 国家、ASN 和兼容入口时间右边界不同 | 记载实际行为，拼接时按记录集合处理 | 后续接口统一及兼容策略经确认并验证后更新 |
| 旧零分母返回 0、稀疏缺行与未知容易混淆 | 同时写明现有返回行为与正确解释条件 | 需建立具体结果家族的连续性与缺失规则 |
| 国家与 ASN 并列峰值选取不同 | 明确当前选择规则，不宣称统一 | 实现统一后同步例子及调用合同 |
| 综合资源变化混合单位并丢失方向 | 保留为旧排序辅助，业务比较使用单族带符号值 | 需确认新的排序指标及兼容策略 |
| 事件记录、修订数、开始数与并发数不同 | 分别定义；历史生命周期缺口显式保留 | 需有相应生命周期和事件身份去重证据 |
| ASN 默认候选、Top N、窗口名单与时点成员不同 | 答案明确候选范围；不从窗口名单推出时点成员 | 需完整候选或逐 ASN 时点证据 |
| 趋势采样点、完整窗口峰值与连续时长不同 | 分别描述；缺口不插成零或连续状态 | 需资格与连续性证据支持对应推断 |
| 计算组件已实现但没有统一 HTTP 入口 | 使用目录标记接入边界，不编造调用路径 | 需接入实现、合同和验证完成 |
| 有接口但所选日期／事件结果未配置、失败或未知 | 查询时判断，文档不硬编码全面可用 | 以实际登记、返回状态和正式验收为准 |

### 已有 HTTP 合同缺口

ASN 档案及关联事件接口的事件窗口模式，实际接收 `event_window`、`event_reference`，并返回 `scope_kind=event_window_selected_asn`；目前 OpenAPI 未完整描述。精确调用限制集中在 [API 导航的已知差异](../usage/api/read-api.md#已知合同差异)，后续变更需同时更新合同、生成类型和验证。本轮仅记录事实，没有顺带修改接口合同或代码。

## 更新方法与后续 docs tool

修改某个指标时，先核对具体结果家族及实际生产／读取路径，再更新该指标的唯一业务说明；跨家族规则只在共用页维护。定义、单位、聚合规则、缺失行为、适用范围和查询入口应一起核对。涉及接口行为变化时遵守项目的 OpenAPI、类型和测试要求，不用文档描述代替实现。

未来面向业务问数的检索内容范围以 `docs/usage/` 为起点。维护页、运行记录、历史评审和来源台账不默认混入业务说明库；需要内部诊断或审计时再明确读取。检索命中应能继续读到包含适用条件的完整章节或原文，不能只用失去上下文的短片段作答。

内容定稿后，再连接已经选定并验证的现成文档检索系统。沿用其索引、查询与读取能力；是否需要名为 `docs` 的薄包装取决于实际接入需求。本页不预设新检索引擎、工具协议、通用执行器或 Agent 架构，也不将候选选型写成已部署能力。
